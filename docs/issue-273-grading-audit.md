# 이슈 273 — 기존 실험 채점과 수행 난점 점검

2026-11-05. 모델 재실행 없이 기존 기록을 검토했다. 운영 저장소와 원본 정답·채점 파일은 변경하지 않았다.

## 결론

기존의 필수 위반 건수를 의미적 실패 건수로 읽으면 안 된다. F19는 내용 소실 없는 목록 들여쓰기 변경이다. v8의 원시 채점 7회에는 낡은 정답에 따른 오탐, 삭제 대신 보존 이동한 사례, 경미한 편집이 섞여 있다. 반대로 채점기가 의미 손실·근거 오귀속을 확인하지 않아 통과한 결과 역시 안전이 증명된 것은 아니다. 지금 필요한 것은 재실험보다 정답과 채점 계약 정정이다.

## 확인 범위와 원본

실험 루트는 저장소 밖 로컬 작업 폴더다.

- `score.py`, `answers_final.json`, v5 배포 조건(`runs_v3`)·v6·v7·v8(`runs`)의 `_score.json` 실패 목록을 대조했다.
- v8 33건×4회 결과 보고를 기계적으로 분류하고, 전체 132회의 완료된 도구 이벤트를 집계했다.
- v8 원시 실패 7회 및 판정이 갈리거나 정답과 충돌하는 F03·F08·F13·F19·F23·F27·F31·F33의 입력 diff, 결과, 관련 본문·출처·도구 조회를 집중 점검했다. v5의 잘못된 삭제 사례도 대표적으로 대조했다.
- 528회 전부의 모든 문장을 독립적으로 의미 재채점한 것은 아니다. 새 합격률·정답률은 산출하지 않는다. `before.md`는 실험 작업자가 수정하기 전의 파일로, 역사적 커밋 적용 **후** 상태다. 역사적 변경 전 내용은 fixture diff로 구별했다.

## 채점기 자체의 한계

1. M1은 본문 줄 문자열의 존재 여부로 사라진 줄을 찾는다. 들여쓰기 변경도 삭제+추가로 센다. 새로 들어온 본문 줄의 의미·범위를 직접 검증하지 않으며 줄의 위치·중복 개수도 충분히 표현하지 못한다. 따라서 과검출과 누락이 모두 가능하다.
2. M2는 이름이 ‘무손실’이지만 실제로는 새 근거 줄의 형식과 좌표가 `added_coords`에 포함되는지만 확인한다. 원문 사실이 보존됐는지, 삭제 사실이 출처에 있는지, 좌표가 해당 주장까지 뒷받침하는지는 확인하지 않는다. `rounds`나 기존 인용 좌표를 포괄하는 검사도 아니다. 새 `## 근거` 제목까지 new_ev에 들어가 형식 실패를 일으킬 수 있다.
3. M3은 정답이 thesis/mixed/sourceless이면 어떤 변경이든 실패다. 한 문서 안의 중복 문장과 출처 없는 문장을 따로 처리한 결과를 표현하지 못한다.
4. ‘처치’는 gone/came/new_ev/lost_ev가 하나라도 있으면 참이다. 필요한 세부가 제대로 정리됐는지가 아니라 단순 변경 유무를 센다.
5. raw score는 개별 `answers/Fxx.json`을 읽는다. 별도 `answers_final.json`의 사후 정정과 자동으로 일치하지 않는다. 실제 v8 raw에는 F08=sourceless, F27=sourceless가 남았지만 최종 표에는 각각 copy, either다. 원시 점수와 최종 보고 수치를 섞으면 안 된다.

원시 실패 7회는 F03 sol1, F08 sol1/astra, F13 sol2, F19 sol1, F27 sol1/sol3이다. 이를 ‘위험한 정보 삭제 7회’나 ‘완전히 틀린 판단 7회’로 표현하면 안 된다. F03·F27의 의미·출처 판단이 남으므로 반대로 ‘7회 모두 완전 정답’이라고도 결론 내리지 않는다.

### F19에는 서식 외에 정답 경계도 있다

astra는 F19를 보존했다. 이유는 배포 완료 자체가 아니라 ‘접속자와 불러온 펫이 없으므로 새 entityLoad 처리가 기동 스파이크 원인이 아니다’라는 원인 배제 판단을 새 결론으로 보았기 때문이다. 이 문장은 역사적 커밋에서 새로 추가됐다. v8은 상태 전환을 세부로 정했지만 원인 배제 결론까지 세부라고 정하지 않았다. 따라서 이 실행을 단순 미처리로 단정할 수 없고, F19 자체가 혼합 커밋인지 재판정해야 한다. 솔의 들여쓰기 문제를 면제하는 것과 이 논지 문제는 별개다.

### F03은 보존 쪽의 설명도 강하다

동일 parameter class·training opportunity·optimizer 조건, auxiliary metric으로 primary 실패를 구제하지 않는 규칙은 기존 결과 문서에 새로 명시된 조건이다. sol2와 astra가 바로 이 이유로 보존했다. ‘이미 최종 실험 결과가 있으니 과거 착수 조건은 세부’라는 삭제 쪽 해석과 갈린다. 최종 결과가 과거 조건을 대체하는지, 문서에 처음 명시된 조건을 새 논지로 볼지 기준이 필요하다. copy 하나로 고정해 보존을 모두 오답 처리하지 않는다.

## 실제 수행 난점

### 1. 출처의 잘린 발췌와 원기록을 혼동

F08 `job.json`의 cited #12·#13은 각각 6,000자다. 그 발췌에는 35–57, −5.1, −4.8, 2.372, e-fold가 없다. sol2/3은 read_node만 사용하고 read_cited를 추가 호출하지 않은 채 출처가 없다고 판단했다.

astra는 `read_cited(752ae528#13, query=63/64)`로 −5.1%·−4.8%를 찾았고, `read_cited(752ae528#12, query=e-fold)`로 약 34km·35–57km·한 단계 비교라는 원문을 찾았다. 이는 모델의 분류 기준뿐 아니라 **자료가 잘려 제공된 상태에서 추가 조회가 필요한 문제**다.

기존 보고의 ‘−2.372e−51은 어느 기록에도 없다’도 엄밀하지 않다. 조회 원문에는 −2.3721e−51가 있다. 반올림 표기와 불일치를 구별해야 한다. 이것만으로 v5의 문단 전체 삭제를 정당화할 수는 없지만, 숫자 문자열이 다르다는 이유로 출처 부재를 확정하면 안 된다.

### 2. 입력 안에 있는 자료도 못 찾는 경우

F31 sol2는 출처가 없다고 보존했지만, 해당 작업의 cited `b5ab19fb#7`에는 시험 228건과 산출물 경로가 들어 있다. 다른 실행은 같은 출처를 찾아 삭제했다. 이 사례는 발췌 잘림과 다르게 입력 자료 탐색 누락이다. 전체 프롬프트 길이가 원인이라는 인과관계까지는 이 기록만으로 증명되지 않는다.

### 3. 논지와 사례의 경계가 정답표와 불일치

F23·F33은 네 실행 모두 보존했고 설명도 일치했다. 이를 모델의 능력 부족으로 해석하면 안 된다. F03·F19는 상태·과거 이력 안에 새 조건·원인 판단이 섞여 있다. 프롬프트를 반복 강화하기 전에 정답의 판단 단위를 맞춰야 한다.

### 4. 삭제와 이동이 같은 의미 보존 결과일 수 있음

F13처럼 삭제 대신 출처와 함께 근거 절로 옮긴 실행을 내용 실패로 볼 이유는 약하다. 다만 F27처럼 내용은 남아도 특정 출처가 그 내용을 실제로 진술하지 않는 경우가 있어, ‘보존됐으니 모두 성공’으로 처리할 수도 없다. 내용 보존과 출처 귀속을 두 축으로 평가해야 한다.

### 5. 도구 실행 실패가 주원인이라는 근거는 없음

v8 완료 도구 이벤트 789개: read_node 449, update_node 174, overview 117, read_cited 49. 이벤트의 error/isError 등 구조화 오류 필드 스캔에서는 오류가 검출되지 않았다. 이는 모든 응답 의미가 성공임을 보증하는 검사는 아니지만, 관측된 난점은 셸 실패·도구 재시도보다 자료 탐색·판정 경계에 집중돼 있다.

## 재실험 전에 바꿀 평가 계약

1. 중대한 내용 오류 / 필요한 정리 미수행 / 무해한 절차 차이 / 경미한 서식 차이 / 정답 불확정으로 구분한다. F19의 이번 들여쓰기는 경미한 서식으로 기록한다. 코드 블록·표·목록의 의미를 바꾸는 모든 공백을 일괄 면제하지는 않는다.
2. 문서·커밋의 단일 라벨 외에 주장별 보존·삭제 가능·이동 가능 범위와 반드시 남겨야 할 조건을 적는다. 논지 섞임의 전체 보존 원칙은 별도로 유지한다.
3. 허용되는 결과를 한 문자열이 아니라 결과의 조건으로 정의한다. 같은 정보를 올바른 출처와 함께 보존한 이동을 삭제와 무조건 다른 오답으로 세지 않는다.
4. 내용 보존, 출처 귀속, 수정 범위, 실제 재검토 완료를 각각 검증한다. M2를 무손실 검사라고 부르려면 실제 내용 검증이 필요하다. vault.diff에 rechecks.jsonl 문자열이 있다는 것만으로 완료를 확정하지 않는다.
5. 발췌의 잘림·검색 필요 여부를 작업 데이터에 드러낸다. ‘제공 발췌에 없음’과 ‘확인한 출처에 없음’을 구분한다. 이는 프롬프트 분리와 별도의 입력 개선 변수다.
6. F23·F33의 정답 정정과 F03·F19·F27의 재판정부터 완료한다. 최종 정답 한 벌과 버전·사유를 고정하고 원시·최종 집계가 같은 것을 읽도록 한다. 사후 재채점임을 명시한다.
7. 기존 결과를 이 계약으로 먼저 재채점한다. 그 뒤 남는 오류를 대상으로 한국어 프롬프트 분리 실험을 설계한다. 현 시점에는 새 성능 수치를 내거나 v8을 불합격/완전 합격으로 확정하지 않는다.

## 한계

v8 전체 결과·도구 이벤트의 구조 점검과 문제 사례의 심층 대조이며, 전 버전 모든 주장에 대한 완전한 재채점은 아니다. v5의 새 규칙 삭제 문제는 대표 사례에서 여전히 실질적 우려가 있어, 이번 오탐 발견을 과거 오류 전체의 면제로 확대하지 않는다. 원문 로그·정답은 보존했고 재실험은 하지 않았다.
