# 대화 원료의 저장 경계 교정안

2026-09-20. 구현·통치문서 대조와 교정 기록. 사용자 승인 후 아래 문안을 시행령에 반영했다.

헌법 4조 3항의 전량 포착 대상은 **해당 세션의 대화 기록**이다. 시행령 §2.2는
읽은 파일 전문을 범위 밖으로 두고 §2.7은 사용자 발화와 에이전트 응답을 한 라운드로
정한다. 현재 구현은 이를 하네스 이벤트 대부분의 JSON 직렬화로 넓혔다.

최초 포착 구현 `b9452b1`부터 Codex는 `event != "message" or role == "assistant"`인
payload를 그대로 저장했다. 파일/혼합 명령 결과에만 참조 치환을 적용했으며, 그 참조의
`source`에 실행 인자를 다시 실었다. Claude도 thinking·tool_use를 포함한 content 배열을
그대로 직렬화했다. 암호문·메타데이터·코드 인자가 새 필드로 들어와도 기본 경로가 수용했다.
검사는 원문 누락·접두부 호환을 확인했지만 읽을 내용과 실행 부산물의 저장 경계를 검사하지 않았다.
명칭이 구현자의 판단에 영향을 줬는지는 확인되지 않는다. 재현 가능한 원인은 허용 목록 없는
포착과 그 경계를 빠뜨린 검사다. 구현 안에서는 이를 `dialogue`와 `native transcript`로 구분한다.

## 시행령 §2.2 대체 문안 — 승인 반영

> 2. 포착 범위는 세션의 대화 기록, 곧 사용자 발화와 사용자에게 제시된 에이전트 응답이다.
>    이 내용은 임의로 요약하거나 길이로 잘라 저장하지 않는다. 하네스 내부 추론·암호문·
>    전송 메타데이터는 포착 범위 밖이다. 작업 중 읽은 파일의 내용 전문, 도구의 실행
>    인자·결과 전문과 첨부의 바이너리는 원본 위치·식별자와 내용 해시 참조로 대신한다.
>    실패·중단과 입력 없는 자동 실행의 구분은 남기며, 이를 새 사용자 발화나 성공으로
>    바꾸지 않는다. 이 경계는 저장 전에 적용하며, 읽을 때 숨기는 것으로 대신하지 않는다.

## 구현과 검증 범위

- 새 자동 포착은 `dialogue-v1`의 명시적인 내용 유형만 저장한다. 사용자와 에이전트의
  보이는 문장은 원문 그대로 보존하며, 도구 인자/결과·첨부는 식별자와 해시로 참조한다.
  도구 참조도 매 호출마다 길게 반복하지 않고 라운드당 참조 하나와 검증 해시로 묶는다.
- 이전 codec은 기존 기록 검증에만 사용한다. 새 기록에 과거 codec을 적용하지 않으며
  새 codec 불일치 뒤 과거 codec으로 우회하지 않는다.
- 이미 저장된 원료의 번호·바이트·출처 해시·완료 영수증은 이번 패치로 덮어쓰지 않는다.
  기존 자료의 읽기 선별본은 호환 경로이고 새 저장 계약을 대체하지 않는다.
- 대량의 암호문·메타데이터를 추가해도 새 저장본이 커지지 않는지, 긴 실제 발화가
  온전히 남는지, 참조가 원본 해시와 맞는지, 기존 기록 뒤 새 codec을 안전하게 붙이는지 검사한다.

참조된 도구의 상세 사실을 나중에 재검증하려면 하네스 원본의 보관이 필요하다. 원료에
남은 에이전트의 결론만으로 도구 실행 결과가 독립 검증됐다고 주장할 수 없다. 이는
시행령의 파일 전문 참조와 같은 보관 의존성이며, 비용 감소와 함께 명시할 한계다.

## 로컬 재생 결과

실제 하네스 기록에서 세 라운드를 새 codec으로 재생했다. 모델 호출은 0회이며,
원래 하네스 파일과 기존 raw 파일의 해시가 그대로임을 확인했다. 단위는 문자 수다.

| A | 5,334,825 | 36,641 | 99.313% |
| B | 1,134,696 | 12,422 | 98.905% |

실패했던 성장 실행 계획을 로컬에서 다시 구성하면 기본 선택이 9건에서 총 3건으로,
입력 프롬프트는 95,871자에서 18,161자로 줄었다. 원래 복구 snapshot은 유지한 비교다.
신규 Scope 작업은 최대 3라운드이며, 600초 기본 제한은 유지한다.

선별 읽기와 세 작업군의 총량·순환 제한을 포함한다.
