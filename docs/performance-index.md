# #16 읽기·캐시 개선 실측 — 2026-09-22

raw나 대장만 바뀌어도 검색기는 노드를 전부 파싱하고 BM25를 다시 만들었다.
제목 하나의 조회도 전수 계약 색인을 요구했고, 군집 순회는 일반 노드마다 디렉터리 여부를 stat했다.

변경은 기존 색인의 의존성을 나누는 데 한정한다.

- 제목은 기존 이름 후보만 파싱한다. 같은 제목의 복수 정상 후보는 거부하고, ID 조회는 전수 유일성 검사를 유지한다.
- 전체 지문과 노드 지문을 구별한다. 비노드 변경은 참조 이름표를 새로 읽고 노드 계약과 BM25는 재사용한다. 전체 지문이 같으면 노드 지문도 재사용한다.
- 군집 디렉터리 판독에는 scandir의 DirEntry를 사용한다.

불완전 관측이나 mtime의 racy 구간은 여전히 캐시 재사용을 거부한다. 본문과 해시는 같은 바이트에서 만든다.
리파스 파일의 소속은 노드 열거와 같은 `space_of`로 판정한다. 지문에는 실제 소속과 링크 목적지도
포함하므로 크기·mtime이 같은 대상으로 바뀌어도 기존 후보·파싱 캐시·BM25를 재사용하지 않는다.
별도 저장소·증분 갱신 대장·새 의존성은 추가하지 않았다.

## 교차 측정

Windows 11 / Ryzen 7 9800X3D / NTFS / Python 3.11.9. 기준 코드는 main `86c9745`의 읽기 경로다.
같은 합성 vault에 구판·수정판의 독립 프로세스를 붙이고 순서를 번갈아 바꾸며 **순차** 호출했다.
5천 노드는 cold·변경 5회 / warm 25회, 2만5천은 3회 / 15회다.
cold는 애플리케이션 캐시 초기화이며 OS 디스크 캐시를 비웠다는 뜻이 아니다.
아래 값은 리뷰 수정 후 두 크기를 순차로 다시 잰 결과다. 회귀 수트와도 겹쳐 실행하지 않았다.
측정기의 `idx` 지역변수가 이전 색인을 붙잡던 오류를 고쳤으며, 각 cold 반복에서 weakref로
이전 Index가 수거됐는지 확인한다. 그 참조를 의도적으로 복원한 대조 실험은 검사에 걸렸다.
아래는 handler wall time의 중앙값(ms)이다. p95·p99·CPU·파싱 건수는
[CSV](../benchmarks/results/index-20260922.csv)에 있다. RSS도 수정된 측정기로 다시 기록했다.
RSS는 Python 할당자가 보유한 페이지를 포함하는 프로세스 작업 집합이다.
분위수는 (n−1)q 순위의 선형 보간이다.

## 남은 비용

- 첫 검색은 전수 BM25 구축이 필요하다. 이번 교차 측정에서는 5천 1.86→1.97초, 2만5천 13.29→14.70초로 줄지 않았다.
- 반복 제목 조회도 5천 13.58→16.78ms, 2만5천 54.33→74.12ms로 증가했다. 링크 소속·목적지 검사를 포함한 현재 판의 비용이며, 모든 읽기가 빨라졌다고 보지 않는다.
- 노드 본문 변경도 전수 재구축한다. 이 PR은 #16 전체를 닫지 않는다.
- 각 읽기의 전체 파일 지문 순회와 프로세스별 BM25 메모리는 남는다.
- 시간 분포는 이 기기의 제한된 반복 결과이며 운영 p99 보장이 아니다. raw만 바뀌는 비율도 측정하지 않았으므로 전체 사용자 체감 개선율로 환산하지 않는다.

## 재현

Windows에서 엔진 의존성이 설치된 Python을 사용한다. 두 checkout을 같은 기준에서 비교한다.
합성 fixture를 새 경로에 만들며 운영 vault에 `--mutate`를 사용하지 않는다.

```powershell
py -3.11 benchmarks/bench_index.py fixture --root E:/tmp/osk-perf-5000 --nodes 5000
py -3.11 benchmarks/paired_index.py --before E:/path/to/baseline/_governance/_engine --after E:/path/to/patch/_governance/_engine --root E:/tmp/osk-perf-5000 --output paired-5000.jsonl --repeat 5 --warm 25
py -3.11 _governance/_engine/tests/test_regression.py
```

`bench_index.py run`은 다중 프로세스 및 노드·raw·대장 변경도 측정한다.
`paired_index.py --only`는 특정 연산만 재측정한다.
