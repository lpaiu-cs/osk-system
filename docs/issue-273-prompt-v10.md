# Issue 273 — v10: 출처 시각과 논지 영향 판정

v8 검토 이력과 v9 엔진·실험·100건 육안 검토는 `619c088`에 보존했다. v9 프롬프트 파일과 이전 동결 실험 산출물은 변경하지 않는다. v10은 별도 선택하는 실험판이며 설치 인스턴스에 배포하지 않는다.

## 네 가지 판정

각 커밋의 원래 unified diff(-/+)와 문맥을 비교해 `judgment`를 하나 선택한다.

| judgment | 의미 | 허용되는 처리 |
|---|---|---|
| 결론·범위 변경 | 새 논지 추가 또는 결론·규칙·적용 조건·한계 변경 | 커밋 전체 kept |
| 신뢰도 변경 | 결론은 유지하지만 근거의 강도·확실성 변경 | 커밋 전체 kept |
| 논지 불변 | 위 변화 없는 사례·수치·진척·표기 변경 | 세부별 deleted/moved/kept/held |
| 미확정 | 논지 영향 판단 근거 부족 | held |

두 변화가 함께 있으면 결론·범위 변경을 우선한다. 단순 사례 증가는 신뢰도 변경의 충분조건이 아니다. 논지와 세부가 혼재하면 전체 보존 규칙을 유지한다. 과거 보류 횟수만으로 미확정을 세부 처리로 우회하지 않도록 기존 반복 보류 예외는 제거했다.

검증기는 커밋 내 판정 불일치와 판정/행동 모순을 거부하고 복원을 안내한다. 이는 저장 후 검증이며 의미를 대신 판정하거나 편집 전에 거래적으로 차단하는 장치는 아니다. 실제 새 논지를 논지 불변으로 오분류하는 문제는 의미 평가가 필요하다. 추가 도구 왕복은 없고 기존 보고에 judgment 필드만 추가한다.

## 출처 날짜

`transcripts.read`는 기존 라운드 경계·본문·해시를 그대로 두고 정확한 원본 시작 행의 시각을 `source_timestamp`로 제공한다. Claude는 라운드의 첫 user UUID, Codex는 해당 turn_id의 task_started, Kiro는 executionId의 turn_start, Antigravity는 해당 USER_INPUT step을 사용한다. 시각이 없는 형식은 미상이다. ISO 날짜·시각과 명시적인 시간대가 있어야 하며 UTC로 정규화한다. 날짜만 있거나 시간대가 없거나 같은 ID의 시각이 충돌하면 추정하지 않는다.

`cite_round`는 엔진이 원본을 읽어 인용하는 경우에만 이 시각을 인용 머리말에 보존한다. caller-supplied 인용에는 시각을 만들어 넣지 않는다. 원본 read_cited 응답에서도 시각을 볼 수 있다. 기존 인용 파일을 소급 수정하지 않으며, 예전 인용에 시각이 없으면 v10에서도 미상이다. 원본이 남은 옛 인용을 일괄 역추적하는 작업은 포함하지 않는다.

v10 입력 준비는 인용 머리말의 정규화 시각에서 KST 날짜를 계산해 `date_label`을 제공한다. 여러 라운드가 모두 같은 KST 날짜로 확인될 때만 단일 날짜를 준다. 여러 날짜에 걸치거나 일부 시각이 없으면 미상이다. 다른 파일/기억의 생성·수정일이나 본문 속 사건 날짜를 대용하지 않는다. 날짜 계산의 원재료는 엔진 계획에 보존하되 모델 입력에는 중복 전달하지 않고 date_label만 준다.

- 확인됨: `2026-11-06`
- 확인 안 됨: `날짜 미상 (관측: 2026-11-06)`

관측일은 입력 준비 당시 엔진 날짜다. 모델은 date_label을 그대로 사용하고, 검증기는 새로 작성하거나 변경한 근거 줄의 날짜가 정확히 일치하는지 검사한다. 기존 줄에 내용을 합칠 때도 제공된 날짜로 맞춘다. 수정하지 않은 옛 근거 줄은 이번 범위가 아니다. 날짜 검사도 출처가 주장 내용을 실제로 입증하는지까지 보증하지 않는다.

## 프롬프트·실험 실행

한국어 추상화+재검토 지시문은 v9 3,647자 → v10 3,617자다(작업 JSON 제외, 토큰 수 아님). 재검토만 하는 지시문은 동일하다. 엔진 파일은 `_governance/_engine/osk/prompts/issue-273-v10-*.ko.txt`, 검토용 사본은 `docs/prompts/`에 둔다.

기존 러너를 재사용하며 `--prompt-version v10`을 지정한다. 기본 버전 v9를 유지하고, 같은 출력 폴더에 다른 버전의 완료 결과가 있으면 재사용하지 않고 거부한다. 새로운 출력 폴더를 사용한다.

```powershell
python benchmarks/abstraction_v9.py preflight --prompt-version v10 --fixtures <PRIVATE_FIXTURES> --output <NEW_PRIVATE_OUTPUT> --vault <VAULT>
```

`run`도 같은 버전 인자를 받는다. 기본은 `--ephemeral`이며 원본 CLI 세션 로그를 영구 보존하지 않는다. `--retain-trace`를 명시한 진단 실행에서만 압축 원본 로그를 수집한다. 로그 저장 자체가 모델 입력을 늘리는 것은 아니지만, 이번 관측으로 기본 영구 보존을 정당화하지 않는다.

## 검증 범위

미니 vault에서 v9 호환, 네 판정과 결과의 일관성, 날짜 누락/범위/KST 변환, 틀린 확정 날짜와 올바른 수정, 신규 인용과 원본 읽기의 timestamp 보존을 검사한다. 실제 모델 비교 재실험과 설치 인스턴스 배포는 별도이며 이번 커밋에 포함하지 않는다.

- `test_abstraction.py`: 13개 통과.
- `test_integration.py`: 111개 항목 확인. 실행 도중 엔진 수정으로 6개 항목(7개 하위 오류)에 StaleEngineError가 발생했으며, 코드 수정 종료 후 해당 6개를 별도 재실행해 모두 통과했다. 나머지 항목은 원래 실행에서 통과했다.
- `test_codex_forks.py`: 26개 통과.
- `test_growth.py`: 70개 중 POSIX 전용 2개 제외. StaleEngineError가 발생한 1개를 수정 종료 후 재실행해 통과했으며 나머지 67개도 통과했다.
- `benchmarks/test_abstraction_trace.py`: 로그 수집/누락/재조회 분류와 버전 혼용 방지 3개 통과.

총 221개 항목 통과(오염된 실행의 재검증 포함), 플랫폼 조건 2개 제외. 전체 릴리스 회귀가 아니라 변경 관련 시험이다.

실제 F04/F13/F51/F78/F93의 과거 스냅샷을 임시 clone에서 읽어 v10 입력을 생성하는 preflight도 5/5 통과했다. 모델 호출 없이 단일 커밋·v10 버전·가용 출처별 date_label을 확인했고 임시 clone은 제거했다. 결과는 저장소 밖 로컬 작업 폴더에 있다.
