## 미룬 설계

[v5.1 계획의 미룬 설계](v5.1-milestones.md#미룬-설계)에서 닫히지 않은 셋이다. [v5.5.0](v5.5-milestones.md)으로
옮겼다(2026-11-01). 본문은 여기 둔다.

- [ ] **보류의 부분 완료.** 확인하지 못한 주장 하나가 15라운드 묶음을 붙잡지 않게 한다. 2026-10-07
  설계안은 사용자가 보류했다. 그 설계안은 ACK의 열린 항목과, 일부 라운드만 다시 여는 `repair_pending`
  틀이다.
- [ ] **근거 노드의 분화 기준.** `## 근거` 절이 커졌을 때 「〈주장〉 — 근거」 노드로 떼는 기준(줄 수·글자
  수)을 실측한 뒤 정한다.
- [ ] **정기 실행 Codex 명령의 구독 사전 확인.** 사전 확인이 vault 경로에서 실패하면 정기 실행이 멈추는
  동작 변경이라 미뤘다. Codex 설정의 `forced_login_method`가 이미 API 로그인을 막는다.

## 근거 참조의 노드·비노드 분리(#272)

`derived-from`은 노드만 받고, 비노드 근거는 노드 끝 근거 절에 적는다. 재검토는 노드 사이에만 둔다. vault
밖 파일은 등록한 외부 루트 안의 것만 근거로 받는다. 결정과 이유는
[사료](../_governance/records/2026-10-31-reference-and-evidence-section.md)에 있다.

- [x] **통치문서 개정(#277).** 헌법 제8조 「참조」와 근거 절(6항), 시행령 §1 5항·§2 8항 등, Mechanism §1
  6항·§6-1 4항·§8 9항 등.
- [x] **1단계 — 좌표와 근거 줄(#278).** 짧은 좌표의 기록 색인, `read_cited`가 받는 근거 줄 좌표와 이어진
  라운드, `cite_round`의 `coordinate`, 검증기 `evidence-section`의 좌표 해석.
- [x] **2단계 — 외부 루트(#279).** `_ledger/roots.jsonl`과 `.osk/roots.json`, `osk roots`, 별칭 좌표의 해석과
  끊김의 세 분류.
- [x] **3단계 — 쓰기·증류·재검토 전환(#280).** `derived-from`의 비노드 대상 거부, 증류 출처와 영수증의 근거
  절 확인, 재검토의 비노드 추적 중단, 참조 위상 검사의 근거 절 좌표.
- [x] **4단계 — 이행(#284).** 비노드 `derived-from` 약 2,244건을 `지지` 줄로 옮기고, 본문 근거 링크 18건과
  근거 절 형식 위반 38건을 정리하며, 이행 기록을 남긴다. 검증기 활성화는 이행 뒤 사용자가 정한다.
  - 엔진은 이행 명령 `osk evidence migrate`를 낸다. 인스턴스 이행과 손으로 하는 정리는 출시 뒤에 한다.

## 함께 내는 것

- **동기화 데몬(#254·#266·#283).** 원격 없는 vault에도 커밋만 하는 데몬을 등록하고, setup이 확인해 적은
  대상으로만 보내며, 멈추면 세션 시작과 `doctor`가 알린다. 옛 vault가 Git에 싣던 `.osk/`는 추적만 푼다.
- **CLI 런처(#256·#282).** vault 루트의 `osk-cli.sh`·`osk-cli.cmd`가 `PYTHONPATH`와 venv 경로를 대신한다.
- **새 릴리스 알림(#255·#276).** 에이전트가 `--ack`로 받았다고 기록할 때까지 세션 시작마다 싣고, 운용 안내
  [OPERATE-AGENT](OPERATE-AGENT.md)(#250)를 가리킨다.
- **프로젝트 키(#271·#274).** 대화 중 하위 폴더로 옮겨도 시작한 폴더의 키를 쓰고, Claude-Data의 scratch 작업
  공간도 일회성으로 판별한다.
- v5.3.1–v5.3.3 출시분은 `main`에서 이었다.

## v5.4.1

v5.4.0 인스턴스 적용 뒤 남은 일 셋이 모두 사용자 작업이었다. 사용자는 비개발자의 편의를 함께 따져, 모든 일에
허락을 받지 않고 합리적인 선에서 자동화하라고 정했다(2026-11-01). 사료는
[2026-11-01-validator-auto-activation](../_governance/records/2026-11-01-validator-auto-activation.md).

- [ ] **검증기 자동 활성화(시행령 §11 3항 개정 #287, 엔진 #288).** 기록이 없는 규칙은 세션 훅의 분리 작업이
  하루 한 번 재서 위반이 0이면 켠다. 해제와 재활성화만 사용자가 정한다.
- [ ] **이행 명령의 단말 확인을 뺀다(#288).** `osk evidence migrate --apply`는 본문을 바꾸지 않고 노드마다
  전후를 이행 기록에 남기는 기계적 변환이라 사용자 전속 행위가 아니다. 갱신 뒤 에이전트가 바로 실행한다.
- [ ] **입력 훅의 계수와 반복 주입(#275, 사용자 결정으로 함께 낸다).**
  - 하네스가 사용자 차례에 끼워 넣은 알림뿐인 입력(작업 완료 알림·목표 이어가기 등)은 사용자의 입력이
    아니다. 9·15턴 계수에 세지 않고 문맥도 싣지 않는다.
  - 이 대화가 이미 전문으로 받은 조직 검토(같은 key·snapshot·구간)는 한 줄로 접는다. 시작과 바뀐
    작업은 다시 전문이다.
  - 한 번의 주입에서 허브 트리는 대화 검토 블록에만 싣는다.
