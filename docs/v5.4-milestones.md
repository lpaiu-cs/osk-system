# v5.4.0 미룬 설계와 포착 정합 마일스톤

v5 계열의 견고함을 마저 다진다. v6.0.0은 이 base 위의 확장이다(2026-10-23 사용자 결정). 이 판은 v5.1
계획에서 미룬 설계 가운데 남은 셋과, v5.3.0 출시 전 점검에서 찾은 Claude 되감기의 처리를 다룬다.
v5.3.1에서 옮긴 운영 관측과 평가도 이 판에서 한다.

- 작성일: 2026-10-23. [v5.3.0 계획](v5.3-milestones.md)에서 옮겼다. 옮긴 항목의 본문은 원래 문서에 두고
  여기서는 가리킨다.
- 2026-10-24: v5.3.1을 빠르게 내려고, 정기 성장 실행을 일주일 관찰해야 하는 문제와 그 운영 기간에 묶인
  평가를 v5.3.1에서 옮겼다(사용자 결정).
- 상태: 계획. 출시 조건과 순서는 착수할 때 정한다.
- 추적: GitHub 마일스톤 v5.4.0.

## 미룬 설계

[v5.1 계획의 미룬 설계](v5.1-milestones.md#미룬-설계)에서 닫히지 않은 셋이다.

- [ ] **보류의 부분 완료.** 확인하지 못한 주장 하나가 15라운드 묶음을 붙잡지 않게 한다. 2026-10-07
  설계안은 사용자가 보류했다. 그 설계안은 ACK의 열린 항목과, 일부 라운드만 다시 여는 `repair_pending`
  틀이다.
- [ ] **근거 노드의 분화 기준.** `## 근거` 절이 커졌을 때 「〈주장〉 — 근거」 노드로 떼는 기준(줄 수·글자
  수)을 실측한 뒤 정한다.
- [ ] **정기 실행 Codex 명령의 구독 사전 확인.** 사전 확인이 vault 경로에서 실패하면 정기 실행이 멈추는
  동작 변경이라 미뤘다. Codex 설정의 `forced_login_method`가 이미 API 로그인을 막는다.

## 포착 정합

- [ ] **Claude 되감기로 버린 턴(#235).** 되감기는 전사의 행을 지우지 않고, `last-prompt` 행에
  `rewound: true`와 되감은 지점을 남긴다. osk는 이 표식을 읽지 않아, 버린 턴이 검토·보존 대상에 남는다.
  - 고칠 방향: Codex의 되돌리기(#208)와 같은 틀로 다룬다. 검토 전의 버린 턴은 추적에서 뺀다. 검토한
    턴을 되감았을 때의 처리는 따로 정한다.
  - 이미 추적한 대화의 경계는 #218의 `prompts_since`처럼 바꾸지 않는다.

둔다.

  Scope 작업 단가, 묶음 첫 요청의 냉시작, 공급자별 작업:검토 비, 주간 한도 조정의 첫 계산을 잰다.
