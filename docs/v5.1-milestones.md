# v5.1.0 의미 품질과 남은 설계 마일스톤

v5 계열이 다지는 견고함 가운데 의미 품질을 맡는다. v5.0.0([성장 경로 개선](v5.0-milestones.md))이
포착·복구·연결·처리의 경계를 닫은 뒤, 승격과 분화가 의미를 보존하는지 평가하고 v5.0.0에서 미룬
설계를 정한다.

- 작성일: 2026-10-07. 버전별 마일스톤 분리(2026-10-07 사용자 결정)에 따라 v5.0.0 마일스톤의 M5를
  옮기고, 미룬 설계와 열린 이슈를 모았다. 번호와 본문은 옮기기 전과 같다.
- 상태: 계획. v5.0.0 출시 뒤 착수한다. 출시 조건과 평가 규약은 착수할 때 정한다.

## M5 Scope에서 Domain으로 승격하고 주장을 분화한다

기존 후보 비교와 본문 구간 검토를 사용한다. 먼저 긍정·부정 예제를 고정한 뒤 후보 선정과 안내가
의미 판단을 방해하는지 확인한다. 구조 이동 수나 새 노드 수에 목표를 걸지 않는다.

- [ ] 평가 전에 평가 집합의 크기·판정자·통과 문턱·판정이 갈릴 때의 처리 방식을 확정한다(#136에서 옮김).
- [ ] 기존 주장에 새 근거가 더해지는 사례, 적용 조건이 다른 독립 주장, 프로젝트 실행 기록, 일반화할 가치가 없는 사례를 평가 집합에 포함한다.
- [ ] 같은 주장·조건은 기존 노드를 갱신한다. 새 Domain 주장은 적용 범위·반례·선택한 출처·사용하지 않은 후보의 이유를 남기고 실제 저장본을 확인한다.
- [ ] 여러 주장이 섞인 노드는 주장별로 나눌 때 결론·조건·정정 이력·근거를 보존한다. 새 노드 재판독과 양쪽 허브 연결을 끝낸 뒤 원문의 해당 구간을 접는다.
- [ ] 새 최상위 군집·보호영역·경계 이동은 기존 통치 규율에 따른다. 현재 범위에서 처리할 수 없는 제안은 구체화한 뒤 상신한다. Person 분석으로 범위를 넓히지 않는다.
- [ ] 평가자는 출력 형식과 별개로 의미 보존을 판독한다. 기준 사례의 누락·허위 일반화가 없어야 하며, 가치 없는 사례를 억지로 승격하면 실패로 처리한다.
- [ ] 정보 회귀 금지: 옛 라운드는 날짜를 붙인 이력으로만 더하고 현행 주장을 옛 내용으로 바꾸지 않는다. 작업자 지시는 PR #140이 넣었다. 고정 사례와 의미 평가가 남았다.
- [ ] 편집 손실은 감시하지 않고 비춘다. 전문 치환의 응답이 흘린 옛 단위를 `dropped`로 돌려준다(2026-10-06 사용자 결정, PR #148). 에이전트가 흘린 것을 실제로 되살리는지 고정 사례로 본다.
- [x] 대화 검토는 노드의 분할과 자리를 정하고, 조직 검토는 허브의 분화를 맡는다. 두 검토에는 그 scope의 허브 트리를 싣는다(2026-10-06 사용자 결정, Mechanism §9-4 3항 개정, PR #155). 일반 쓰기도 `overview(session=…)`의 `hub_tree`로 같은 트리를 본다(2026-10-07 사용자 결정, PR #157). 실제 분화가 일어나는지는 운영에서 본다.

완료 기준은 고정된 사례에서 기존 노드 재사용, 필요한 승격, 필요한 분화, 이유 있는 유지 판단을
구별하는 것이다. 명시 일괄 실행에서 만든 Domain은 그 실행 경로의 성과로 표시한다.

주요 접점: `osk/growth.py`, `osk/organization.py`, 기존 worker 안내;
[본문 구간과 의미 보존 계약](hub-growth-review.md).

## 미룬 설계

- [ ] **보류의 부분 완료(M4에서 옮김).** 확인하지 못한 주장 하나가 15라운드 묶음을 붙잡지 않게 하는
  방식을 정한다. 2026-10-07 설계안(ACK의 열린 항목, 일부 라운드만 다시 여는 기존 `repair_pending`
  틀)은 사용자가 보류했고 다시 검토한다.
- [ ] **근거 노드의 분화 기준.** `## 근거` 절이 커졌을 때 「〈주장〉 — 근거」 노드로 떼는 줄 수·글자 수
  기준은 실측한 뒤 정한다(2026-10-05 사용자 보류).
- [ ] **재검토 전파에 Link를 넣을지**(#92).
- [ ] **fork 권한 모델의 대안**(#85). v5.0.0 M2의 실제 관측(Codex 일괄 실행은 MCP만 쓰고 셸 0회,
  PR #159)을 판단 자료로 쓴다.
- [ ] **정기 실행 Codex 명령의 구독 사전 확인.** Codex 설정의 `forced_login_method`가 이미 API
  로그인을 막는다. 사전 확인이 vault 경로에서 실패하면 정기 실행이 멈추는 동작 변경이라 미뤘다
  (2026-10-07 사용자 결정, PR #159).
- [ ] **되감긴 턴의 처리(v5.0.0 M2에서 옮김).** 이미 추적한 턴을 사용자가 되감으면 그 턴이 현재
  계보에서 빠지고, 포착이 `native round identity prefix changed`로 멈춘다. 실제 사례 1건의 원인이
  되감기였다 — Codex history의 새 페이지가 이어받은 바이트 경계가 저장한 마지막 라운드의 시작과
  같았다(2026-10-07 확인, 파서 결함이 아니다). 저장한 raw·좌표·검토 커서를 보존한 채 빠진 턴을
  되감긴 것으로 표시하고 새 턴을 이어 추적하는 방식을 정한다. Claude의 되감기도 같은 꼴인지
  확인한다(2026-10-07 사용자 결정으로 미룸).
