## delete / move / keep의 경계

먼저 새 논지인지 판단한다. 논지와 세부가 섞였으면 커밋 전체를 보존하는 v8 규칙을 유지한다. 세부만 있는 커밋에서 아래 순서를 적용한다.

| 판정 | v9 제안 |
| --- | --- |
| delete | 문장의 모든 사실·값·조건이 근거인 다른 기억 문서 또는 target의 해당 근거 줄에 이미 있음. 본문 중복만 삭제 |
| move | 위 삭제 조건에 해당하지 않는 비노드 출처의 세부. 출처 유래와 본문에 남는 주장과의 지지·조건·반례 관계를 확인하여 해당 근거 줄로 이동 |
| keep | 논지·혼합 변경, 출처 없는 자체 관찰, 또는 삭제·이동 조건이 성립하지 않는 내용 |

`held`는 네 번째 편집 행동이 아니다. 물리적으로 keep하고 판단을 보류했다는 보고 상태다. 추상화의 held와 재검토 작업의 deferred도 구별한다.

**이 경계는 v8 번역만으로 얻어지는 규칙이 아니라 v9에서 제안하는 명확화다.** v8은 기록 출처까지 삭제 조건에 포함하면서 같은 기록의 세부를 이동하라고 하여 두 조건이 겹쳤다. 원 설계 §7의 ‘다른 근거 문서의 사본 삭제 / 비노드 출처의 세부 이동’ 구분을 채택하고, 이미 근거 줄에 있는 내용은 중복 추가하지 않도록 했다. 노드/기록 구분은 derived-from에 들어 있다는 사실이 아니라 실제 참조 대상의 종류로 한다. 레거시 derived-from의 대화 기록을 기억 문서로 취급하지 않는다.

추가로 기존 인용 좌표도 이동 후보에 포함한다. v8의 ‘이번 커밋이 추가한 좌표 또는 rounds’보다 넓은 규칙이다. 다만 날짜·좌표가 있다는 것만으로 이동하지 않는다. 본문 주장과의 관계와 유래가 확인돼야 하며, 진행·계획을 근거 절에 모으는 방식은 허용하지 않는다. 요지만 저장된 출처는 상세의 불일치와 구별하되, 실제 쓰기 라운드와의 연결이 없으면 보류한다.

따라서 F08·F13의 기존 좌표 이동은 새 기준에서 검토할 수 있지만 자동 정답은 아니다. F31처럼 과거 정답이 copy였다는 사실만으로 v9에서도 delete라고 고정하지 않는다. 출처 종류·기존 근거 줄·본문 주장 관계를 다시 확인한다. **v8의 기존 결과는 v8 기준으로, v9 결과는 미리 고정한 v9 기준으로 평가한다.**

## 생성기에 맡기는 입력 정돈

1. **범위와 순서.** 선택 key·manifest·work_order를 보존한다. 같은 target의 추상화는 한 작업 key에만 배정하고, 그 결과를 읽는 재검토를 뒤에 둔다. 원본과 인용 문서를 별도 독립 작업으로 쪼개지 않는다. 문서·출처를 공유하면 같은 묶음에 두고, 서로의 쓰기를 읽을 수 있는 묶음도 합친다. 독립 묶음 사이에서도 원래 작업 순서를 유지하며 우선 순차 실행한다.
2. **중복 제거.** 같은 변경을 change.diff와 abstraction.commits[].diff에 두 번 넣지 않는다. 커밋별 diff를 한 번 싣고 change는 해당 커밋을 참조한다. 서로 다른 변경 범위는 같은 diff로 합치지 않는다. 커밋 직전 내용과 현재 저장본을 구별하고, 현재까지 남아 있는 변경 위치를 제공한다.
3. **출처 목록.** 전체 좌표·대상 종류·조회 가능 여부를 유지한다. 마지막 20개만 남기는 조용한 절단을 제거하고, 텍스트 발췌 예산을 따로 제한한다. 중복 인용은 좌표별로 한 번만 싣되 어떤 변경이 참조하는지는 남긴다. `_raw`·`_cited`·비표준 기록 이름을 엔진의 해석 경로로 처리한다.
4. **재검토의 6,000자 예산.** 기존처럼 무조건 앞부분을 자르지 않는다. 문서 diff의 변경 표현·수치와 출처 안의 문자열 일치 위치를 이용해 앞뒤 구간을 선택한다. 여러 구간은 겹침을 합치고, 필요한 인접 문맥에 예산을 쓰도록 한다. 문서 diff의 줄번호를 대화 줄번호로 대입하지 않는다. 문맥 경계에서 잘리면 제한적으로 늘릴 수 있게 하되 원문 전체를 무제한 제공하지 않는다. 확장 폭과 절대 상한은 실험 조건으로 별도 고정한다.
5. **기계적으로 보장할 범위.** 일치 위치, 인접 행, 가까운 문단 경계·Markdown 표 헤더 같은 구문 정보까지다. 관련 조건·반례·단위를 의미적으로 모두 찾는다고 보장하지 않는다. 일치가 없으면 ‘관련 구간 자동 선택 실패’로 표시하고 조회 좌표를 남긴다. 숫자 표기 차이만으로 출처 부재를 확정하지 않는다.
6. **잘림 표시.** 출처 좌표·종류·원문 해시·길이, 발췌 위치, 생략 여부를 함께 제공한다. 메타데이터를 못 얻으면 모른다고 표시한다. 시스템 알림·중복 안내·판단과 무관한 도구 추적은 제거하되, 사용자 지시·정정·실패·관측 결과는 보존한다.

위 수정 대상은 **재검토 작업을 만드는 생성기의 초기 입력**이다. read_cited가 라운드 전문을 무조건 반환하도록 바꾸거나 query 방식을 개편하자는 제안이 아니다. 추가 조회는 현재 도구를 사용하고, 입력으로 충분하면 반복 호출하지 않는다.

## held_parts와 이번 변경의 대응

`held_parts`는 과거 보류 인용문·이유·당시 문서 상태와 검토 시점을 보관한다. 새로 제안하는 `held_matches`는 과거 보류 부분이 이번 변경에서 어떻게 이어졌는지 알려 준다.

```json
{
  "held_parts": [
    {"id":"h1","part":"이전에 보류한 원문","reason":"남았던 쟁점","reviewed_state":"sha256:...","reviewed_at":"..."}
  ],
  "held_matches": [
    {"held_id":"h1","commit":"...","current_part":"이번 대응 원문","match":"confirmed","changed_again":true}
  ]
}
```

11-06 개발 구현은 과거 인용문이 변경 전 본문에서 유일하고, 당시 본문 해시·검토 시각이 맞으며, 하나의 치환 구간이 현재의 유일한 문장으로 이어질 때만 `confirmed`를 준다. 그 밖에는 `uncertain`이며 `absent`를 별도로 내지는 않는다. 여러 커밋을 통과하는 위치 추적이나 보류 이력의 자동 수집은 구현하지 않았다. 합성 시험으로 대응을 검사했지만 이번 33개 역사적 사례에는 실제 이전 모델의 보류 이력을 넣지 않았으므로 연속 검토 성능은 미측정이다.

`confirmed`이며 `changed_again=true`일 때만 v8의 ‘다시 바뀐 보류 부분은 세부 규칙으로 처리’가 적용된다. 출처가 없으면 그 규칙 안에서도 보존한다. 이전에 보류됐다는 이유로 새로 생긴 논지를 건너뛰거나 삭제를 강제하지 않는다. 판정은 여전히 모델이 하며, 생성기는 동일 부분과 시간 관계만 대응시킨다.

## 엔진·결과 계약

실제 저장, rechecked 기록, 반환 결과 반영, 미완료 여부는 엔진이 확인한다. 논지가 유지됐는지나 근거가 주장을 실제로 뒷받침하는지는 기계적 완료 판정만으로 증명되지 않으므로 의미 채점으로 남긴다.

- 본문 저장에는 기존 expect_hash 검증을 유지한다. **프롬프트의 설명을 줄이는 것이 검증 제거를 뜻하지 않는다.** 충돌 오류 응답에 ‘현재 본문을 다시 읽고 변경 부분의 판단을 갱신한 후 새 해시로 저장하라’를 제공한다. 다른 오류를 해시 충돌로 취급하지 않는다.
- 일반 재검토의 필수 `manifest`, `domain:[]`, `scope:[]`와 recheck 형식은 유지했다. 불필요한 업무 설명만 제거했다.
- 추상화 보고의 key·commit·outcome·part·reason은 v8 이름을 유지했다. **한 커밋에서 서로 다른 부분을 삭제·이동·보류할 수 있도록 여러 항목을 허용하는 점은 새 계약이다.** 동일 부분의 중복·겹침 보고는 거부하고, 전체 보존 항목과 부분 편집 항목을 같은 커밋에 섞지 않는다. 커밋 전체가 mixed라면 전체 kept 한 항목이다.
- 엔진은 선택 범위, 실제 저장 diff, 출처 좌표 유효성, 허용 편집 범위, 재검토한 원본 버전, 보고와 저장의 대응을 검증해야 한다. 단순 문자열 검사를 의미적 무손실 검증이라고 부르지 않는다. 저장 후 응답 소실 시 이미 적용된 부분을 재적용하지 않도록 상태에서 재개한다.
- 초안 당시 growth._validate_packet은 abstraction 필드를 허용하지 않았다. **후속 개발 엔진에서는 v9 계획에 한해 필드를 받아 검증·기록하고, 실제 저장본 및 선택 입력이 일치하는 영수증이 있어야 완료로 인정한다.** 일반 작업의 계약은 유지한다. 초기 발췌·보류 대응·충돌 응답도 연결했다. 독립 묶음의 일반 실행 구조와 운영 배포는 이번 재검토 모델 비교 범위 밖이다.

## F19와 정답·채점

F19에서 기존 두 줄의 들여쓰기만 바뀌고 내용이 남은 것은 사용자 판단대로 경미한 서식 정돈으로 기록한다. 빈 줄이나 의미가 같은 목록 정돈을 정보 삭제와 같은 실패로 세지 않는다. 반대로 코드 블록·조건의 적용 범위·목록의 의미 있는 종속 관계를 바꾸면 의미 오류다.

F19의 새 원인 배제 결론이 논지인지 여부는 별도다. 서식 오탐을 바로잡았다고 해당 이동 전체가 정답이 되는 것은 아니다. F03·F27의 논지·귀속 쟁점도 정답을 동결하기 전에 해결한다. F08은 사용자 지정대로 입력 설계 오류에 따른 재채점 대상으로 분리한다. 기존 판정과 정정 판정을 함께 남긴다.

채점은 필요한 정리를 수행했는지, 논지·정보를 보존했는지, 귀속과 근거 역할이 맞는지, 비대상 의미를 바꿨는지, 서식만 달라졌는지를 나눠 기록한다. 검사 대상이 없어 M1/M2가 통과한 결과를 작업 정답으로 세지 않는다. copy라는 단일 라벨만으로 delete/move/keep을 정하지 않는다.

| v8 한국어 ↔ v9 규칙의 한국어 통합판 | 판정 규칙·문구 개정 | 업무 구성·실행 단위·입력·도구 |
| v9 한국어 통합판 ↔ 업무별 필요한 규칙만 선택 | 업무 지침 선택 | v9 의미·언어·작업 순서·입력·도구 |
| 선택 지침 단일 실행 ↔ 독립 묶음 순차 실행 | 문맥 분리 | 같은 작업·v9 규칙·언어·도구 |
| 독립 묶음 순차 ↔ 독립 묶음 병렬 | 동시 실행 | 묶음·규칙·언어·도구 |

v9 전문은 v8의 의미 보존 직역본이 아니다. 이것과 v8 영어를 바로 비교한 차이를 언어 효과 또는 분리 효과라고 부르지 않는다. 입력 발췌 수정도 별도 변수다. 먼저 결함을 정정한 같은 입력을 조건들에 쓰고, 과거 입력 결과와 비교할 때는 입력이 달라졌다고 표시한다. 정답은 각 규칙에 맞춰 사전에 고정하되 실제 논지·정보 손실은 공통 기준으로 함께 평가한다.

현재 33건은 개발 표본으로 취급한다. 언어 대조용 직역본·통합 대조판과 별도 보류 표본은 아직 작성·동결하지 않았다. 혼합 업무의 분리 효과에는 동일한 혼합 작업 묶음이 필요하며, 재검토 표본만으로 다른 업무의 효과를 주장하지 않는다. 병렬화는 이후 실험이다.

비용은 모든 실행의 입력·출력·캐시 토큰, 추가 조회, 재시도와 미완료 비용을 포함해 잰다. 속도는 전체 완료 시간과 총 실행 시간을 나눠 본다. 한국어 글자 수나 파일 길이를 토큰 절감의 증거로 삼지 않는다.
