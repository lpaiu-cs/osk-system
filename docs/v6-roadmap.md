# v6 계열 로드맵

v5.6.0을 독립으로 평가했을 때(2026-11-10) 약하다고 나온 것 가운데 아직 남은 것을, 고칠 순서로 적는다. 판마다의
계획 문서는 그 판을 착수할 때 쓴다 — 이 문서는 순서와 그 까닭만 든다.

- 작성일: 2026-11-15. 순서와 판 배정은 에이전트가 안을 냈고 사용자가 정했다("이 순서대로 로드맵 문서와 GitHub
  마일스톤을 정리할까요?"에 "네, 정리해").
- 상태: 1번을 냈다(v6.0.0, 2026-11-15). 3번에 들어갔고, 4번의 첫 일(질의 구성 견주기)을 했다 —
  [v6.1 계획](v6.1-milestones.md). 묶음마다의 출시 조건은 착수할 때 정한다.
- 추적: GitHub 마일스톤 v6.0, v6.1, v6.2, "v6.3 이후".
- [v5.7 계획](v5.7-milestones.md)의 항목은 모두 여기로 옮겼다. v5.7.0은 내지 않는다 — 다음 판은 v6.0.0이다.

## 어디서 왔는가

평가는 엔진과 통치문서, 운영 저장소의 집계를 보고 축마다 강약을 매겼다. 점수는 평가자의 주관이라 여기에 옮기지
않는다. 축과 그 뒤의 일만 적는다.

| 축 | 평가 때 | 그 뒤 |
|---|---|---|
| 쓰기 무결성과 복구 | 강하다 | 그대로다 |
| 코드 유지보수성 | 보통 | 구조 개편(0~6단계)으로 풀었다 — [계획과 기록](v6.0-refactoring.md). 아직 릴리스 전이다 |
| 검색과 회상 | 약하다 | 남았다 |
| 비용 | 약하다 | 남았다 |
| 복잡도에 견준 가치 | 약하다 | 남았다 |
| 프로젝트 사이의 재사용 | 가장 약하다 | 남았다 |
| 남이 쓸 수 있는가 | 약하다 | 이 로드맵에 넣지 않았다(아래 "넣지 않은 것") |

평가의 권고는 넷이었다: 재사용을 잰다(#19의 기준선), 검색을 지속 색인으로 옮기고 선제 회상(#245)을 앞당긴다,
쓰이지 않는 제도를 걷는다, 결함을 고친다(#319–#324). 넷 다 아래에 들어 있다.

## 묶음마다

### 1. 구조 개편을 낸다 — v6.0.0

**냈다(2026-11-15).** 정식 회귀 통과 2,392·실패 0·생략 7, 전체 업그레이드 행렬 62칸 통과, CI 세 잡 통과. 운영
저장소의 사본에서 옛·새 엔진의 포착을 견줘 대화 커서 567개 가운데 564개가 같았다 — 다른 셋은 엔진 탓이 아니다
(첫 포착이 이미 덧붙인 라운드 둘, 진행 중이던 대화 하나).

- 담는 것은 `v6.0-devel`의 구조 개편이다. 기능을 더하지 않는다. [v6.0.0 계획](v6.0-milestones.md)이 후보로 모았던
  확장 둘(#166, #245)은 뒤의 묶음으로 갔다.
- 재구성에 실려 들어온 동작의 변경이 있다. 릴리스 노트에 따로 적는다 — 적어도 구조 개편 계획의 "교차 검토"가
  꼽은 PR 셋(#350, #351, #356)과, 검증기의 검사 하나를 뺀 #370이다. 릴리스 PR에서 전부 추린다.
- 릴리스 PR에서 전체 CI 행렬과 정식 회귀를 돈다.
- 남은 결정: 개발 전용 도구(구조 개편 계획의 "정할 것").

### 2. 지금 깨져 있는 것 — v6.0.x

- **#321** — 쓰기 표면이 형식이 틀린 관측 줄을 그대로 저장하고, 활성 규칙이 뒤늦게 검증을 실패로 만든다. 운영
  저장소의 검증기가 2026-11-14에 이 규칙으로 실패였다(노드 다섯의 관측 줄 여덟).
- **#320** — Windows에서 대장을 읽는 프로세스가 추가 중인 프로세스와 겹치면 손상으로 잘못 알린다.
- **#324** — GitHub가 라이선스를 인식하지 못하고, 저장소 토픽에 코드에 없는 것이 남아 있다.
- **운영 저장소의 옛 형식 이행** — `osk doctor --migrate`. 엔진의 일이 아니라 운영의 일이고, 사용자가 확인하고
  적용한다. 6의 "옛 형식의 지원"이 이것을 전제로 한다. 남은 양은 구조 개편 계획의 7단계 조사에 있다.
  **했다(2026-11-15, v6.0.0을 적용한 뒤).** 옛 자리의 인용 기록 173개를 루트 `_cited/`로 옮겼고(충돌 0), 절 제목
  465개를 `# 관측`으로 바꿨다(보류 0). 적용 뒤 `osk doctor --vault`는 이행 셋 모두 옮길 것이 없다고 하고, 끊긴
  참조는 0이며, 근거 재검토 후보는 늘지 않았다.

### 3. 계측의 기준선 — v6.1

- **#19** — 고정 과업과 고정 저장소로 표면의 효용을 판마다 다시 재는 기준선이다.
- 그 과업에 회수(적용할 노드가 검색의 위쪽에 드는가)와 재사용(다른 프로젝트에서 얻은 지식이 실제로 쓰이는가)을
  재는 것을 넣는다. 4와 7이 이 수로 판단한다. 성장 실행의 비용과 완료율도 같은 틀에서 잰다 — 5가 쓴다.
- 구조와 무관한 일이라 1을 기다리지 않아도 된다.

### 4. 회상 — v6.1

- **지속 색인.** 지금은 프로세스마다 색인을 다시 세운다. 입력 훅에서 세우면 2.73초가 걸렸다(노드 2,304개,
  2026-10-24의 실측 — [v6.0.0 계획](v6.0-milestones.md)의 "선제 회상 주입"). 이것이 풀려야 아래 둘이 선다.
- **#245** — 선제 회상 주입. 그 계획이 적은 단계 가운데 "색인 유지 → 판정자 없는 섀도 측정"까지를 이 판에서
  한다. 주입할지는 측정한 회수율을 보고 정한다. 사용자의 말과 노드의 말이 달라 적용할 노드가 상위 5건에 없던
  실측이 출발점이다.
- **#261** — 여러 세션이 한꺼번에 다시 연결되면 MCP 기동이 30초 제한을 넘는다. 색인을 세우는 시간이 원인인지부터
  잰다 — 그렇다면 지속 색인이 함께 푼다.
- **#260** — `read_node`가 `id`·`session` 인자를 받지 않아 에이전트의 호출이 거듭 실패한다. 표면의 설명 예산이
  8,000자 가운데 7,972자를 쓰고 있어(2026-11-14 운영 저장소의 검증기 보고), 인자를 더하려면 다른 설명을 줄여야
  한다.

### 5. 비용 — v6.1

- **#319** — 성장 기록부가 57일에 28.9 MB이고, 읽을 때마다 전체를 다시 읽는다.
- **#315** — 재검토의 전파 앞에서 논지를 판정해, 주장이 바뀐 변경만 전파한다([설계](recheck-thesis-gate.md)).
- **성장 실행의 완료율.** 평가 때 운영 저장소의 성장 실행은 절반 넘게 끝까지 가지 못했다. 3의 기준선으로 다시
  재고, 무엇이 막는지부터 본다. 이슈는 그때 세운다.

### 6. 줄이기 — v6.2

통치문서의 개정이 드는 것을 한 번에 묶는다. 개정안을 한 번 내고 한 번 비준한 뒤, 통치문서는 다시 고치지 않는
것을 기본으로 둔다.

- **쓰이지 않는 제도.** 평가 때 운영 저장소에 사건이 0건이었고 pin의 쓰임도 보이지 않았다. 사건부와 pin을 걷을지
  남길지를 정한다. 이슈는 착수할 때 세운다.
- **#297** — 설명적 중심성 E. 계산만 하고 어디에도 쓰이지 않는다. 쓸 곳을 정하거나 걷는다.
- **옛 형식의 지원.** 끊으려면 순서가 있다: 운영 저장소의 이행(2) → 새 엔진이 남은 옛 형식을 알아보고 알리는 자리
  → 조항 일곱의 개정 → 끊기. 전제와 잰 것은 구조 개편 계획의 7단계 조사에 있다. 엔진 파일을 없애면
  v3.20.0에서 바로 올리는 길이 깨진다는 것도 거기에 있다.
- **#322** — 비밀값 필터가 흔한 토큰 모양 여덟을 놓친다. 패턴을 더하면 그 토큰이 든 기존 기록의 처리를 정해야
  하고, 패턴의 표가 규범(Mechanism §9)에 있어 개정이 든다.

### 7. 프로젝트 사이의 재사용 — v6.3 이후

- 평가 때 Domain 노드 가운데 밖에서 참조된 것이 여덟에 하나였다. 프로젝트 사이의 직접 참조는 규범이 금지하므로,
  지식이 건너가는 길은 Domain으로의 승격과 회상 둘이다. 4가 회상 쪽을 먼저 연다.
- **#178** — Scope에서 Domain으로의 승격과 주장의 분화가 의미를 보존하는가. 평가의 규약부터 정한다.
- **#298** — 추상화 검토. 설계와 시험 기록이 있고 도입은 보류 중이다(#300).

### 8. 확장 — v6.3 이후

- **#166** — 기억의 시간 지역성. 일정과 유통기한이 있는 지식.
- **#296** — Claude의 자동 메모리와의 관계. scope 기억으로 대체할지 호환할지.

## 넣지 않은 것

- **남이 쓸 수 있는가.** 평가가 약하다고 본 축이지만 #324 말고는 넣지 않았다. 공개 제품으로 키울지에 달린
  일이고, 그 결정이 없다.
- **#323**(Claude fork의 도구 봉쇄 확인), **#200**(검색 응답에 파손 파일을 실을지). 자리를 정하지 않았다 — 마일스톤
  없이 둔다.
- 평가 때의 수(성장 실행의 완료율, 참조의 수 등)는 이 문서를 쓰며 다시 재지 않았다. 3의 기준선이 다시 잰다.
