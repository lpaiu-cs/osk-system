## 기계 검증과 복구

Sol의 F56·F59·F63·F76·F83에서 검증 오류 응답이 발생했고 모두 수정 뒤 추상화 검사를 통과했다. Terra에는 검증 오류 응답이 없었다. Sol의 F56·F83은 추상화 기록은 남았지만 후속 재검토 상태가 pending이었다. 실패를 숨기기 위한 재실행이나 사후 저장 수정은 하지 않았다.

검증 거절은 삭제 보존 위치, 보고한 인용 부분, 편집 범위, 이동 보고와 실제 근거 변경의 불일치, 보존 보고와 실제 편집의 불일치에 관한 것이다. 의미 검토를 하지 않았으므로 모든 거절이 타당했는지 또는 검사 오탐이 있었는지는 아직 판단하지 않는다.

F76 Sol은 검증 오류 8회를 거쳐 385.406초 후 통과했다. 오류 피드백이 항상 빠른 복구로 이어진 것은 아니며 이 비용도 위 시간·토큰에 포함한다. 검증 도구의 오류 응답 총 12회와 전체 도구 오류 응답 14회를 구분한다.

## 입력·구현·검증

- [실행 전 계약](issue-273-v9-100-experiment.md)에 따라 100개 `(commit,path)`와 58개 문서를 선정했다. 원래 33개 fixture는 바이트 그대로 유지했고 추가 67개는 결과를 보지 않고 선정했다.
- 각 작업은 커밋 하나다. 혼합 커밋 보존·삭제 판단 규칙은 유지했다. 삭제의 preserved_at 검사와 실행 중 verify_abstraction, 날짜 미상·엔진 관측일, 표기 정돈 보존을 추가했다.
- 문장 일치나 의미 동등성을 엔진의 삭제 허용 조건으로 사용하지 않는다. 서로 다른 표현도 보존 위치의 종류·존재 검사를 통과할 수 있다.
- 입력 준비 점검 100/100 통과. 준비 중 코드 수정과 겹친 F82의 stale-engine 중단은 코드 고정 전 재점검했고, 모델 실행 실패로 합산하지 않았다.
- 실행 종료 후 엔진·프롬프트·실행기 등 92개 파일의 해시와 사본 일치를 확인했다. 100개 fixture 해시도 유지됐고 같은 사례의 모델 간 입력 불일치는 0건이다.
- 새 추상화 시험 11개 통과, 기존 growth 68개 통과·2개 건너뜀, growth_status 13개 통과·1개 건너뜀. 총 92개 통과·3개 건너뜀. Python 컴파일과 git diff --check도 통과했다.
- 운영 설치본 배포·전체 릴리스 회귀·반복 안정성·업무 병렬화는 검증하지 않았다. 33개 기존 결과와 이번 결과는 별도 보존한다.
