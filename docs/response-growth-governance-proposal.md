# 최종 답변 Stop 기준 성장 실행 — 개정 제안

상태: 2026-09-21 사용자 문안 승인 후 Mechanism §9-3 1항에 반영했다.

대상: Mechanism §9-3 1항의 복구 대기 문단.

현재 문단을 다음으로 교체한다.

> **아직 통합하지 못한 복구 대기(§9-2 4항)도 세션 시작과 대화별 검토 시점에
> 싣는다.** 별도 구독 실행기가 연결된 하네스에서는 성공한 최종 답변의 Stop을
> 실제 대화 ID별로 세어 9회마다 그 대화의 검토를 백그라운드에서 실행한다.
> 도구 호출을 위한 중간 응답·실패·중단·같은 완료의 중복 통지는 세지 않는다.
> 실행기는 원대화와 같은 하네스·실제 모델로 일회성 fork를 만들며, 구독 인증을
> 확인하지 못하면 API 과금으로 대체하지 않는다. 별도 실행기가 없는 하네스는
> 기존 9·15 user 턴 주입을 유지한다. 복구할 때는 새 요약을 다시 추가하라는
> 지시 대신 현재 저장본의 엔트리를 정리·보존해 자리를 만드는 일을 준다.
> 퇴출 항목이 0건이어도 싣고, 주입·실행·캐시 재사용 자체는 검토 완료나
> 지식 성장의 증거가 아니다. 포착·실행·보존 확인이 실패하면 검토 대기를
> 유지한다. 거부된 초안을 복원했다고 말하지 않는다.

일일 Domain 재검토·보호영역 승인·정돈 세션의 원료 보존 제외는 변경하지 않는다.
Stop 실행은 자기 대화의 미검토 완료 라운드를 최대 9개 선택하며, 오래된 대기는
기존 일일 catchup도 이어받는다. 캐시 수명과 적중률은 실측·운영 문서에서 구분한다.
