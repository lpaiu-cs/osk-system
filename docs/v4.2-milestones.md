# v4.2 성장 경로 개선 마일스톤

v4.2는 대화가 포착된 뒤 검토·보존·연결·정돈을 거쳐 다음 작업에 쓰이는 경로를 완성한다.
v4.1.3에서 복구한 실행 경로를 출발점으로 삼고, 남은 실패를 재현한 뒤 기존 구현을 보완한다.
새 노드 수나 프로세스 종료 코드만으로 성장 완료를 선언하지 않는다.

- 개발 브랜치: `v4.2-devel`
- 기준: `main` / `v4.1.3`, `edf9523fe32c5d9a08ab41b95dd464b3d0fe433f`
- 작성일: 2026-10-03, 동기화: 2026-10-06(`v4.2-devel` `4b1247aa`, PR #152 병합 뒤). 진행과 결정은 [#136](https://github.com/lpaiu-cs/osk-system/issues/136)이 추적한다.
- 상태: M1은 [PR #128](https://github.com/lpaiu-cs/osk-system/pull/128)로 병합했다. M2·M3·M4는 일부 항목을 병합했고 남은 항목이 있다. M5·M6은 평가 규약을 정하기 전이다. 병합과 실 인스턴스 적용은 별도로 기록한다.
- 통치문서 개정은 v4.2.0 릴리스 선언으로 비준한다: 원본 턴 추적·인용 기록(PR #131), 헌법 1조 3항 선의 가정(PR #146), Mechanism §4-1 재검토 완료의 `rechecked`(PR #151).
- 실행 범위: 기존 Stop 검토와 사용자가 명시적으로 실행하는 한정 일괄 검토. 예약 기능은 추가하거나 활성화하지 않는다.

## 출발점과 해결 범위

v4.1.3의 [PR #127](https://github.com/lpaiu-cs/osk-system/pull/127)은 Claude Desktop의
버전 아래 빌드 디렉터리 탐색, 선택하지 않은 대화의 포착 오류가 실행 전체를 실패로 만드는 판정,
실패·미완료 일괄 실행이 Stop 재검토를 막는 판정을 고쳤다.
v4.1.2의 최종 결과 파서 수정도 기준선에 포함한다. 이들을 새 마일스톤의 성과로 다시 세지 않는다.

앞선 운영 조사는 2026-09-26 05:42:35부터 2026-10-03 07:19:39까지의 KST 기록을 사용했다.
이는 v4.1.3 적용 전 관측이며, 적용 후 실패율을 뜻하지 않는다. 이 문서는 실패 유형과 검증 계획만
보존한다. 개인 전사, 노드 본문, 대화 식별자와 운영 원장은 공개 저장소에 싣지 않는다.

| 남은 문제 | 확인한 범위 | 다음 판단 |
|---|---|---|
| 포착 오류와 미검토 원문이 함께 누적 | 전사 소실·신원 불일치·착지 미정, 검토 대기를 관측 | 안전하게 복구할 수 있는 항목과 외부 조치가 필요한 항목을 분리 |
| 저장 후 출처·허브 연결 누락 | 실제 누락을 수동으로 보수 | 일반 쓰기·증류·이동 중 어느 경로가 검증을 빠져나갔는지 재현 |
| 오래된 퇴출·정돈·재검토 항목 잔존 | 기존 순환 선택과 checkpoint가 있어도 대기가 남음 | 선택되지 않음·실행 실패·의미 판단 보류를 나누어 검증 |
| 승격과 의미적 분화의 증거 부족 | 사용자 요청으로 만든 Domain과 이동 사례 확인 | 기존 노드 갱신, 새 주장, 구조 이동을 구별하여 평가 |
| 후속 작업의 개선 미입증 | 보존 영수증과 수동 보수는 확인 | 독립된 후속 작업에서 검색·본문 사용·결과를 검사 |

인증 토큰 갱신 충돌은 처음 한 번 관측했을 때 별도 추론 점검이 성공해 반복 결함으로 확정하지 않았다.
10-05 실측에서 2026-09-25 이후 Claude 작업자 실행 86회 중 14회(16%)가 같은 메시지로 추론 전에
끝났으므로 반복 결함이다. osk가 다시 시도하지 않아 그 검토 기회를 잃는다. M2에서 다룬다.
오래된 MCP 연결이 새 파일을 적재하지 못한 상태 역시
디스크 배포와 실행 프로세스를 구분해서 확인할 항목이다.

## M1 성장 상태와 근거를 일치시킨다

기존 상태 조회와 원장 판독을 보완한다. 먼저 익명 fixture와 읽기 전용 보고서로 기준선을 고정하고,
필요한 필드가 실제로 없을 때만 기록 형식을 확장한다.

- [x] 포착 대상 대화, 포착한 미검토 라운드, 복구 검토, 조직 구간, 퇴출, 근거 재검토의 분모를 각각 표시한다. 포착하지 못한 꼬리를 검토 대기 라운드에 합치지 않는다.
- [x] 선택 작업 완료, 원문 저장, 지식 보존, 현재 연결, 의미 판단, 후속 재사용을 별도 결과로 낸다. `deferred`, `no_value`, 빈 선택, 오류 종료의 의미를 유지한다.
- [x] 근거 재검토의 기준선 등록·자동 이어받음·직접 판독한 `unchanged`·본문 `updated`·사용자 상신을 구별한다. 근거 제거·대상 소실로 닫힌 작업도 직접 판독 성공으로 세지 않는다.
- [x] 훅 기동, 사용자 지시, 명시 일괄 실행, 과거 예약 실행을 구별한다. 현재 코드의 `work_context="daily"`는 공용 일괄 경로이므로 실제 예약 기동의 증거로 쓰지 않는다.
- [x] 디스크 버전, 현재 MCP의 `engine_rev`·`engine_stale`, CLI 버전·인증·fallback 사유를 같은 관측 시점에 확인한다. 재연결 전 성공을 새 엔진 검증으로 집계하지 않는다.

완료 기준은 고정한 원장을 다시 읽었을 때 모든 집계가 개별 상태와 일치하고, 혼합 버전과 원인 미확인
사례를 따로 설명할 수 있는 것이다. 운영 백로그를 없애는 일은 이 단계의 완료 기준이 아니다.

M2 착수 기준선은 v4.1.3 적용 뒤인 2026-10-03 11:50:04–17:53:01 KST로 닫았다.
기간 내 실행은 Stop 문맥 2건(기록상 완료 1·미완료 1), 명시 일괄 실행은 0건이다.
이는 실행별 엔진 해시가 없는 과거 기록이다. 현재 잔량과 적용 후 신규 실패를 혼합하지
않으며, 이 표본으로 희귀 결함을 제외하지 않는다. 문제는 운영 재관측·고정 사례 재현·
과거 관측만 존재로 구분하고 재현된 결함의 수정은 추가 관측을 기다리지 않는다.

주요 접점: `osk/integration.py`, `osk/growth.py`, `osk/rechecks.py`, `osk/response_growth.py`,
기존 `overview`·상태 조회 표면.

구현의 판독 계약과 실행 방법은 [성장 상태 판독](growth-status.md)을 따른다.

## M2 원본 턴 추적과 중단된 검토를 안전하게 복구한다

기존 전사 재탐색, `repair_pending`, 분할 검토, 연속 실패 fallback을 먼저 재생한다.
원인을 재현한 항목에 한해서 구현을 고친다. 전사를 찾지 못했다는 사실 자체는 식별 검사를
완화하거나 임의의 다른 대화를 붙일 근거가 아니다.

2026-10-04 결정(PR #131, 10-05 병합·v4.2.0 비준 대기)은 세 경로를 구분한다. 기존 `_raw/`의 좌표·본문·검토
영수증은 그대로 유지한다. 새 턴은 기기 로컬 커서에 원본 신원·좌표·내용 해시로 추적한다.
노드에 인용·검증이 필요한 턴만 `cite_round`로 보존하며, 선택하지 않은 대화를 vault에 복사하지 않는다.

새 경로의 완료 항목은 다음 검증으로 닫는다. PR #129·#130의 저장 경로 시험 통과를 새 추적 경로의
검증으로 대신하지 않는다.

- [ ] 전사 이동·소실, 신원·계보 불일치, 같은 턴 ID의 내용 변경, 착지 미정, 열린 꼬리를 재현한다. 실패 단계가 없는 구 상태도 저장된 사실과 실제 원본 재탐색으로 분류하고, 다음 행동과 재개 조건을 표시한다. 빈 필드만으로 입력 없음을 단정하지 않는다.
- [x] 재추적·원본 턴 판독·ACK가 검토 대상 내용 해시를 일관되게 확인한다. 같은 ID의 내용이 바뀌면 옛 snapshot으로 완료하지 않으며, 읽지 못한 원본은 `no_value`로 닫지 않는다. 기존 raw 좌표·바이트·검토 커서·영수증은 보존한다.
- [x] Codex fork의 선언된 계보·페이지 신원·바이트 경계를 검증한다. 부모 턴은 부모의 검토 책임과 원본 신원을 유지하고 자식의 새 작업으로 중복 등록하지 않는다. 부모의 완료·미검토 턴, 열린 꼬리, 다른 Scope, 원본 커서 유실, 구 raw와 새 native 좌표가 섞인 경우를 각각 시험한다. ID 검사 완화만으로 허용하지 않는다.
- [x] 선택 인용의 재시도는 같은 좌표를 반환하고 중복 저장하지 않는다. 반환한 `user_by`·응답 해시·출처는 실제 저장본과 일치해야 한다. 열린 턴이 종료되거나 원본이 복구돼도 과거 인용을 조용히 검증 완료로 바꾸지 않는다. 저장된 정보와 새로 관측한 정보가 다르면 그 차이를 명시한다.
- [ ] 작업자가 최종 결과 묶음을 내기 전, 실행기가 개별 결정을 적용하는 중, 적용 후 응답 전에 각각 중단시킨다. 이미 MCP로 저장된 본문·출처·허브·보존 영수증은 유지하고, 받지 못했거나 적용하지 못한 검토 결정을 완료로 세지 않는다. 다음 실행은 기존 영수증을 확인하고 미완료 선택만 다시 제시한다.
- [ ] 작업자는 MCP와 최종 결과 묶음으로 판단을 전달하고, 실행기는 지원되는 vault 환경에서 기존 검증을 거쳐 적용한다. 같은 하네스·구독·모델·권한 조건을 유지하며 다른 설치의 CLI나 대체 API로 성공을 만들지 않는다. CLI `growth checkpoint`는 수동 사용 경로로 구분한다.
- [x] 12시간 이상 원본 변경이 없는 대화 중 미검토 턴만 명시 일괄 검토에 제시한다. 진행 중·이미 검토한 대화는 제외하고, 필요한 앞 문맥만 한 턴씩 읽는다. 추적한 턴을 모두 검토했을 때만 해당 대화의 user·Stop 계수를 새 주기로 전환한다. 스크립트로 돌린 `codex exec` 실행은 추적·검토하지 않는다(2026-10-04 사용자 결정).
- [x] 출처 정정은 일어난 시점에 등록한다. 정정하는 쪽이 영향받는 검토를 그 자리에서 다시 열고, 다시 연 검토는 정정 좌표와 그 출처를 쓴 노드를 지니고 작업자에게 간다(PR #139).
- [x] 원래 세션이 진술한 도구 결과는 그 세션의 보고로 받는다. 도구 출력의 한정 판독을 만드는 대신 원래 세션을 다시 감사하게 만든 지시문을 고쳤다(2026-10-06 사용자 결정, v4.1.8 PR #143, `v4.2-devel` PR #147). 효과 측정에서 도구 원문을 이유로 한 보류가 9건에서 0건이 됐다.
- [ ] 작업 도중에 보낸 사용자 메시지가 사용자 발화로 남지 않은 사례(1회 관측)를 원본 표현으로 재현하고, 파서가 사용자 발화로 읽는지 고정 사례로 시험한다.
- [ ] 인증 토큰 갱신 충돌로 추론 전에 끝난 작업자 실행을 재현하고, 그 검토 기회를 잃지 않는 처리를 정한다.

PR #129에서 검증한 원본 후보와 확정 경로의 분리, 저장 직후 중단 재생, 기존 raw 검토의 독립성은
이전 저장 경로의 성과로 남긴다. [M2 복구 계약과 시험](growth-preflight.md#v42-m2-원본-경로의-복구와-저장된-raw의-검토)을
새 경로의 검증과 구분한다. PR #130의 fork·구 상태 분류 결과도 해당 커밋의 저장 경로 결과다.

PR #131과의 통합은 계보 판독·`thread_message`·구 상태 진단을 새 추적 경로에 이식하고, 부모 턴의
중복 검토 방지를 함께 검증한다. 계보 파서만 기존 저장 엔진에 먼저 넣어 부모 턴을 자식 raw에
다시 복사하는 중간 상태를 통과로 취급하지 않는다. 기존 `_raw/` 기록을 지우거나 옮기는 정책은
이 마일스톤에 포함하지 않는다.

끝난 대화 항목은 `test_batch_reads_only_the_unreviewed_turns_of_an_ended_conversation`,
`test_complete_review_restarts_the_conversation_cadence`, `test_scripted_codex_exec_run_is_not_tracked_or_reviewed`가
확인한다.

위에서 완료로 표시한 세 항목 — 내용 해시 결속, Codex fork, 선택 인용 재시도 — 은 PR #131의
`e2330e3c`·`db32d2d8`이 구현했고, `tests/test_integration.py`의
`test_changed_original_turn_never_closes_its_old_snapshot`·
`test_recited_turn_reports_the_stored_record_and_what_it_sees_now`와 `tests/test_codex_forks.py`가
익명 재현으로 확인한다. 부모가 추적되지 않거나 다른 Scope에 있으면 부모 턴을 자식에서 빼고

## M3 저장 뒤 출처와 허브 연결을 끝까지 검증한다

`distill`의 재개·영수증 검증은 이미 있다. 수동 보수한 누락을 익명 사례로 바꾸어 일반 MCP 쓰기,

- [ ] 본문 저장 후 출처 또는 허브 갱신에서 중단시키고, 같은 작업 키로 연결을 재개한다. 보존한 본문을 잃거나 노드를 중복 생성하지 않아야 한다.

- [ ] 일반 쓰기의 누락 안내와 기존 조직 검토가 빠진 연결을 다시 발견하는지 검증한다. `derived-from`이 없다는 이유만으로 모든 노드를 결함 처리하지 않고, 주장과 근거의 필요성을 판독한다.

## M5 Scope에서 Domain으로 승격하고 주장을 분화한다

기존 후보 비교와 본문 구간 검토를 사용한다. 먼저 긍정·부정 예제를 고정한 뒤 후보 선정과 안내가
의미 판단을 방해하는지 확인한다. 구조 이동 수나 새 노드 수에 목표를 걸지 않는다.

- [ ] 기존 주장에 새 근거가 더해지는 사례, 적용 조건이 다른 독립 주장, 프로젝트 실행 기록, 일반화할 가치가 없는 사례를 평가 집합에 포함한다.
- [ ] 같은 주장·조건은 기존 노드를 갱신한다. 새 Domain 주장은 적용 범위·반례·선택한 출처·사용하지 않은 후보의 이유를 남기고 실제 저장본을 확인한다.
- [ ] 여러 주장이 섞인 노드는 주장별로 나눌 때 결론·조건·정정 이력·근거를 보존한다. 새 노드 재판독과 양쪽 허브 연결을 끝낸 뒤 원문의 해당 구간을 접는다.
- [ ] 새 최상위 군집·보호영역·경계 이동은 기존 통치 규율에 따른다. 현재 범위에서 처리할 수 없는 제안은 구체화한 뒤 상신한다. Person 분석으로 범위를 넓히지 않는다.
- [ ] 평가자는 출력 형식과 별개로 의미 보존을 판독한다. 기준 사례의 누락·허위 일반화가 없어야 하며, 가치 없는 사례를 억지로 승격하면 실패로 처리한다.
- [ ] 정보 회귀 금지: 옛 라운드는 날짜를 붙인 이력으로만 더하고 현행 주장을 옛 내용으로 바꾸지 않는다. 작업자 지시는 PR #140이 넣었다. 고정 사례와 의미 평가가 남았다.
- [ ] 편집 손실은 감시하지 않고 비춘다. 전문 치환의 응답이 흘린 옛 단위를 `dropped`로 돌려준다(2026-10-06 사용자 결정, PR #148). 에이전트가 흘린 것을 실제로 되살리는지 고정 사례로 본다.

완료 기준은 고정된 사례에서 기존 노드 재사용, 필요한 승격, 필요한 분화, 이유 있는 유지 판단을
구별하는 것이다. 명시 일괄 실행에서 만든 Domain은 그 실행 경로의 성과로 표시한다.

주요 접점: `osk/growth.py`, `osk/organization.py`, 기존 worker 안내;
[본문 구간과 의미 보존 계약](hub-growth-review.md).

## M6 자연 검토와 다음 작업의 재사용을 입증한다

구현·릴리스 검증과 운영 효과를 별도 항목으로 닫는다. 아래 표본 수는 조사 결과가 아닌
v4.2의 제안된 최소 관측 기준이며, 결과를 본 뒤 유리하게 바꾸지 않는다.

- [ ] 파일 배포 후 새 MCP 프로세스의 엔진 해시와 CLI 사전 점검을 확인한다. 기존 연결의 재시작 필요성은 지원되는 재연결 절차로 안내한다.
- [ ] 하네스별로 다음 적격 자연 Stop 10회를 순서대로 관측한다. 보존을 직접 요청한 턴, 수동 재생, 진단 호출은 별도 집계한다. 적격 기준·기간·버전·제외 사유를 먼저 고정한다.
- [ ] 모든 관측 실행이 작업별 완료 또는 원인 있는 대기로 설명되어야 한다. 각 하네스에서 적어도 한 번은 유용한 내용의 검토→보존→출처·허브 완료를 확인한다. 표본이 없거나 부족하면 관측 대기로 남긴다.
- [ ] 독립된 후속 세션에서 이전 지식이 필요한 과제와 무관한 대조 과제를 포함한 최소 6개 쌍을 고정한다. 같은 모델·도구·예산에서 OSK 접근 유무만 바꾸고 순서를 교차한다.
- [ ] 실제 검색·본문 판독·답변에서의 사용을 확인한다. 실행 전에 정한 정답·회귀 기준으로 후속 결과를 판정하고, 단순 인용이나 검색 hit를 개선으로 세지 않는다. 오류·수정 횟수와 시간·토큰 비용도 함께 보고한다.

최소 표본의 목적은 경로가 연결되는지 확인하는 것이다. 전반적인 성공률 향상이나 인과 효과를
확정하는 표본으로 쓰지 않는다. 성장 효과 통과에는 적어도 하나의 유효한 지식 재사용에 따른
사전 정의 오류 감소와 평가 집합의 새 사실 오류 0건이 필요하다. 개선이 없으면 그대로 미입증으로 남긴다.

## 구현과 릴리스 완료 기준

각 단계는 작은 PR로 나누고 문제·재현 입력·수정·독립 재판독 결과를 남긴다.
문서와 익명 fixture를 먼저 고정하고, 기존 기능으로 통과하는 항목에는 구현을 추가하지 않는다.
이번 계획에서 엔진 버전이나 `release.json`을 변경하지 않는다.

- 엔진 변경은 해당 회귀 시험과 `_governance/_engine/tests/test_regression.py` 정식 러너로 검증한다. 새 파일이 필요한 시험은 Git 추적 목록에도 포함한다.
- 정식 배포 전 기존 5개 CI 환경과 업그레이드 행렬을 통과한다. v4.1.3에서의 실제 업그레이드 출발 셀을 포함하고, 레거시 레이아웃을 유지한다.
- Actions 한도로 PR별 CI를 생략한 변경(PR #131 이후)에는 로컬 Windows 정식 러너 기록만 있다. 이를 5개 환경 통과로 적지 않고, 릴리스 전에 합본을 다시 검증해 실제 검사한 SHA·환경을 남긴다.
- 코드·형식 변경의 검증 결과와 M6의 운영 관측 결과를 따로 기록한다. 운영 관측이 남은 후보는 `devel` 또는 시험판 상태로 두고 성장 검증 완료로 표시하지 않는다.
- 최종 완료 보고에는 코드 SHA, 배포 버전, 실제 실행 엔진, 관측 창, 제외 항목, 미결 원인을 적는다. 적용은 기존 내용 결속 갱신 절차를 따른다.

위의 `osk/` 경로는 모두 `_governance/_engine/osk/`를 기준으로 한다.
