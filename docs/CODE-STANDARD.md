# 코드 규범

엔진 코드(`_governance/_engine/`)가 따르는 규범이다. v6 구조 개편([계획](v6.0-refactoring.md))과 함께 시작한다.
통치문서가 **무엇을** 구현할지를 정한다면, 이 문서는 **어떻게** 짤지를 정한다.

바탕은 하나다. **수정은 그 계약을 가진 쪽에서 한다.** 틀린 값을 받는 쪽에서 보정하면 그 값은 계속 돌아다니고,
읽는 사람이 기억해야 할 특례가 하나 는다.

## 규범

1. **층은 한 방향이다.** `kernel → model → store → service → surface`. 위층만 아래층을 import한다.
   - `kernel`: 경로, 시각·식별자, 원자 쓰기, 잠금, 대장. 노드가 무엇인지 모른다.
   - `model`: 노드 계약, 링크, 관측 줄 문법, 이름 규칙. 파일을 읽고 쓰지 않는다.
   - `store`: 색인, 인용 기록, scope 기억, 보호영역, 결속. 저장소와 하네스의 상태를 읽고 쓴다.
   - `service`: 노드 쓰기, 검색, 재검토, 대화 검토, 성장, 배포, 설치.
   - `surface`: MCP 서버, CLI, 훅. 인자를 해석하고 결과를 내보내는 얇은 층이다.
2. **함수 안 import로 순환을 피하지 않는다.** 순환이 생기면 둘이 함께 쓰는 것을 아래층으로 내린다.
   지연 적재는 진입점(surface)의 기동 시간 때문에만 쓴다. 그 밖의 예외는 사유와 함께 구조 시험의 목록에 올린다.
   오래 도는 진입점(MCP 서버)은 엔진을 뜰 때 읽는다. 도는 프로세스는 뜬 시각의 코드를 쥐므로(`osk.epoch`),
   뜬 뒤에 디스크에서 읽는 모듈은 엔진이 갱신된 뒤라면 옛 판 위에 새 판으로 얹힌다.
3. **다른 모듈이 쓰는 이름은 공개 이름이다.** 밖에서 `모듈._이름`을 쓰고 있다면, 그 이름은 이미 공개 API다.
   밑줄을 떼고 제 층으로 옮긴다.
4. **저장소는 전역 상수가 아니라 값이다.** import 시각에 경로를 고정하지 않는다. 진입점이 저장소를 한 번 열고
   (`Vault.open()`), 저장소를 읽거나 쓰는 안쪽 함수는 그 값을 첫 인자 `vault`로 받는다. 안쪽에는 "지금 열린
   저장소"를 돌려주는 전역도, 스스로 여는 함수도 두지 않는다. 여는 자리는 표면 층의 모듈과 각 모듈의 `main`이다.
5. **경계에서 한 번 해석한다.** 도구 인자, 대장 행, 노드 파일은 들어오는 자리에서 형이 있는 값으로 바꾼다.
   안쪽 함수는 그 값을 믿고, `row.get("kind") in (...)` 같은 검사를 되풀이하지 않는다.
6. **검사는 한 곳에 산다.** 같은 규칙을 쓰기 표면과 검증기가 따로 구현하지 않는다. 한쪽만 고쳐지면
   표면이 받은 것을 검증기가 뒤늦게 FAIL로 만든다.
7. **오류는 종류로 말한다.** 계약 위반, 손상(수동 복구가 필요하다), 일시적 실패(다시 하면 된다), 낡은 엔진은
   서로 다른 예외 형이다. 메시지 문자열로 가르지 않는다. `except Exception`은 프로세스 경계에만 둔다:
   훅 진입점, MCP 응답 변환, 데몬 루프.
8. **반환은 실제로 일어난 일을 말한다.** 읽지 못한 것을 "없음"으로, 실패를 기본값으로 바꿔 돌려주지 않는다.
   어떻게 다룰지는 부른 쪽이 종류를 보고 정한다.
9. **함수는 한 가지 일을 한다.** 새 함수는 본문 60줄, 분기 15 이하다. 인자가 여덟을 넘으면 요청을 값 하나로
   묶는다.
10. **주석은 계약과 이유를 적는다.** 무엇을 받고 무엇을 돌려주며 무엇을 보장하는지, 그리고 왜 이렇게 했는지다.
    결함의 내력은 커밋 메시지와 사료에 둔다. 코드에는 불변식 한 줄과 그것을 지키는 시험 이름을 남긴다.
11. **시험 전용 코드는 제품 코드에 두지 않는다.** fixture와 시험용 인자는 `tests/`에 둔다.
12. **한 PR은 한 종류의 변경이다.**
    - 이동: 자리와 이름만 바꾼다. 논리는 한 줄도 바꾸지 않는다.
    - 재구성: 한 모듈 안에서 함수를 가르거나 시그니처를 바꾼다. 동작은 같다.
    - 동작: 결함을 고치거나 기능을 더한다. 시험이 함께 바뀐다.

    이동·재구성 PR이 시험에서 바꿀 수 있는 것은 import 경로와 이름뿐이다. 단언은 바꾸지 않는다.

## 강제

1·2·3·4·7·9항은 구조 시험이 잰다. 엔진을 import하지 않는 `ast` 시험이고, 회귀 수트가 함께 돈다.

```bash
python _governance/_engine/tests/test_architecture.py            # 기준선과 대조
python _governance/_engine/tests/test_architecture.py --update   # 기준선을 지금 상태로
```

- 지금의 위반은 `tests/architecture_baseline.json`에 적혀 있다. 시험은 실측이 기준선과 **같을 때만** 통과한다.
- 위반이 늘면 코드를 고친다. `--update`는 합계가 느는 갱신을 거부한다.
- 위반을 줄였으면 같은 PR에서 `--update`로 기준선을 낮춘다. 낮추지 않으면 그만큼의 여유에 다음 위반이 숨는다.
- 코드를 옮기면 항목의 이름이 바뀐다. 합계가 같거나 줄면 `--update`가 받는다.
- `tangled_modules`만은 느는 갱신을 받는다. 순환에 든 모듈을 둘로 가르면 의존은 그대로인데 수가 늘기 때문이다.
- 새 모듈은 시험의 층 배정표(`LAYERS`)에 올린다. 배정을 바꾸거나 예외를 더하는 것은 시험 파일의 수정이고,
  리뷰에서 사유를 본다.

출발점(v5.6.0)의 합계다.

| 항목 | 뜻 | 합계 |
|---|---|---:|
| `upward_imports` | 아래층이 위층을 import하는 줄 | 16 |
| `lazy_imports` | 진입점 밖의 함수 안 내부 import | 139 |
| `two_module_cycles` | 서로를 import하는 모듈 쌍 | 22 |
| `tangled_modules` | 순환에 든 모듈 | 32 |
| `private_access` | 다른 모듈의 `_이름` 사용 | 210 |
| `broad_except` | 넓은 예외 처리 | 125 |
| `oversize_functions` | 60줄 또는 분기 15를 넘는 함수 | 119 |
| `excess_lines` | 그 함수들이 60줄을 넘긴 줄 수의 합 | 2,763 |
| `excess_branches` | 그 함수들이 분기 15를 넘긴 수의 합 | 1,606 |

4항의 두 항목은 2단계를 시작하며 더했다. 그 항목을 들인 커밋에서의 합계다.

| 항목 | 뜻 | 합계 |
|---|---|---:|
| `vault_fixed_names` | import할 때 저장소에서 고정하는 이름 | 43 |
| `vault_unthreaded` | 그런 이름을 읽거나, 진입점이 아닌데 저장소를 스스로 열거나, `vault`를 받지 않으면서 그런 함수를 부르는 함수 | 580 |

둘 다 2단계가 끝나며 0이 됐다(2026-11-11).

2항의 한 항목은 3단계에서 더했다. 그 항목을 들인 커밋에서의 합계다.

| 항목 | 뜻 | 합계 |
|---|---|---:|
| `late_loads` | 오래 도는 진입점(MCP 서버)이 뜬 뒤에 엔진을 디스크에서 읽게 되는 문: 뜰 때 읽힌 모듈이 함수 안에서 읽는, 뜰 때 읽히지 않은 모듈 | 4 |

문 뒤에서 함께 읽힐 모듈의 수는 세지 않는다. 그 수는 모듈을 가르면 늘지만 문은 그대로다.

5·6·8·10·11·12항은 아직 기계가 재지 않는다. 리뷰가 본다. 개편 단계가 나아가며 잴 수 있는 것부터 시험으로 옮긴다.

## 표면

밖에서 부르는 표면은 코드를 옮겨도 그대로여야 한다. 표면 고정 시험이 MCP 도구의 설명·스키마·순서와 `osk` CLI의
명령·옵션을 `tests/surface_snapshot.json`과 전문으로 대조한다.

```bash
python _governance/_engine/tests/test_surface_snapshot.py            # 기록과 대조
python _governance/_engine/tests/test_surface_snapshot.py --update   # 기록을 지금 표면으로
```

- 이동·재구성 PR에서 이 시험이 실패하면 코드를 고친다. 기록을 고치지 않는다.
- 표면을 일부러 바꾸는 PR은 동작 변경이다(12항). 같은 PR에서 `--update`로 기록을 고치고, MCP 도구 목록의 개정이면
  Mechanism §6-2 7항의 관문을 지난다.
- MCP 스키마는 `mcp`와 `pydantic`이 만든다. 그 판이 기록할 때와 다르면 스키마 대조는 생략(SKIP)으로 남는다.
  `constraints.txt`의 판을 올리는 PR이 기록을 함께 고친다.

## 고칠 때의 순서

결함을 고치거나 새 기제를 더하기 전에 다음을 차례로 본다.

1. 저장소에 이미 있는 답을 찾는다. 같은 일을 하는 함수, 같은 개념의 형, 같은 불변식을 지키는 시험이 있는지 본다.
2. 깨진 불변식을 한 문장으로 적는다.
3. 그 값이 처음 틀려지는 자리를 찾는다. `if` 하나로 시험이 통과하는 자리에서 멈추지 않는다.
4. 그 값을 만든 쪽을 고친다.
5. 같은 값을 받는 다른 곳을 확인하고, 그 결함을 견디려고 두었던 보정 코드를 걷는다.

외부 입력, 권한, 동시성, 손상된 저장본의 복구, 장애 격리처럼 독립된 경계의 방어는 남긴다. 남길 때는 어느 경계인지 적는다.
