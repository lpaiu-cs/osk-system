# v9 Sol / Terra 비교 — 실행 전 기준

2026-11-05. 모델 결과를 보기 전에 고정한 개발 표본 비교다. 모델 재실행은 수정된 v9 엔진·입력 생성기·결과 검증기를 함께 사용한다. 기존 `mock/job.py`나 `deploy.py`는 사용하지 않는다. 운영 vault에 설치하지 않고 역사적 커밋의 독립 복제본에서 실행한다.

- 모델: 기존 비교 기준 `gpt-5.6-sol`, 요청 모델 `gpt-6.1-terra`. Astra를 호출하지 않는다.
- 최종 수정 엔진 비교는 각 모델에 33개 사례를 1회씩, 총 66회다. 추론 강도 `medium`, 회당 제한 900초, 구독 로그인, 같은 MCP 도구와 developer 지침. 원 계획은 2회씩 132회였으나 아래 입력 계약 오류를 발견해 진단 실행을 중단하고 전 사례를 새 입력으로 다시 실행한다. 반복 안정성은 이번 최종 비교에서 측정하지 않는다.
- 실행 파일은 앱의 `CODEX_APP_RUNTIME_CLI_PATH`가 가리키는 Codex CLI 0.166.0-alpha.6이다. PATH의 0.154.0은 Terra를 model_not_found로 거절하여 예비 점검에서 중단했다. 이 호출들은 정식 비교에 섞지 않는다.
- 모델 호출 순서를 사례·반복별로 교차 배치하고 순차 실행한다. 업무 병렬화의 속도 실험이 아니다.
- 입력은 커밋당 diff 한 번, 모든 인용 좌표, diff와 일치하는 구간의 주변 발췌다. 출처당 기본 6,000자, 첫 인접 문맥 창의 제한적 확장 상한 8,000자. 긴 출처에 일치가 없으면 빈 발췌와 no_match를 제공한다. 전체 출처 목록을 마지막 20개로 자르지 않는다.
- 인용 메타데이터, 알려진 세션 연결·자동 CI 활성화 알림, 도구 호출 식별자는 발췌에서 제외한다. 작업의 완료 상태·실행 결과·사용자 정정은 유지한다. 원문 해시·길이·발췌 위치는 원문 기준이며 제외한 알림의 문자 수를 따로 표시한다.
- 전체 계획·원문 스냅샷은 검증용으로 로컬에 보관하며 모델에게 중복 전달하지 않는다. snapshot·manifest를 제외한 작업 내용은 같은 사례에서 동일해야 한다.
- 이전 실험의 33건을 그대로 쓰므로 보류 표본 성능이나 일반적인 하위 모델 성능으로 확장하지 않는다. 이번 비교는 v9에서 두 모델이 이 업무를 수행하는지 확인한다. v8 대비 변화는 언어·규칙·입력이 함께 바뀌어 원인별 효과로 해석하지 않는다.

## 미리 정한 의미 평가

확정군 26건과 경계군 7건을 나눈다. 보존은 target의 기존 논지·정보 보존, 정리는 해당 세부의 적절한 삭제 또는 근거 이동을 뜻한다. outcome 이름만으로 성공을 인정하지 않고 저장 diff와 귀속·정보 보존을 확인한다. 다른 근거 문서/이미 있는 근거 줄을 제시한 삭제는 허용하지만, 비노드 기록에만 있다는 이유의 삭제는 v9와 다르다.

| 사례 | 기대되는 행동 | 이유 |
| --- | --- | --- |
| F01,F05,F07,F09,F10,F11,F12,F16,F17,F22,F23,F25,F28,F30,F32,F33 | 보존 | 새 논지·조건·원인 판단이 포함된 혼합 변경 |
| F06,F15,F21 | 보존 | 지정 출처로 삭제·이동을 정당화하지 못한 상세 |
| F18 | 보존 | 기존 참조의 제목 표기를 명확히 한 변경 |
| F02,F04,F08,F13,F26,F31 | 정리 | 기존 결론에 대한 구현·검증·측정 세부. 출처와 근거 역할을 확인한 처리 필요 |
| F03,F14,F19,F20,F24,F27,F29 | 경계군, 별도 판정 | 과거 조건의 새 논지 여부, 수정된 출처 제공, 원인 배제 결론, 근거 역할, 감사 범위 한정, 귀속, 완료 시점 의미 등에 판단 여지가 있음 |

경계군을 사후 유리한 방향으로 골라 확정군 정답률에 넣지 않는다. 각 모델의 실제 행동과 의미 손실·출처 오귀속을 별도로 설명한다. 확정군의 기준에서도 문제를 발견하면 원래 결과와 정정 결과를 나란히 기록한다.

## 기계 확인과 사람의 판독

엔진은 결과 형식, 선택 커밋, 겹친 보고, 실제 저장 여부, 허용 변경 범위, frontmatter 보존, 인용 좌표와 근거 변경, 재검토 기록을 확인한다. held는 본문 보존과 판단 보류다. 사라진 문장이 다른 말로 온전히 표현됐는지, 목록의 의미가 바뀌었는지, 출처가 주장을 뒷받침하는지는 저장 diff를 읽어 평가한다. 코드가 의미적 무손실을 증명한다고 하지 않는다.

F19의 빈 줄·의미가 같은 들여쓰기 차이는 경미한 서식으로 구별한다. F08은 이전 입력 설계 결함을 정정한 새 시험이며 옛 실패를 모델 능력 부족으로 합산하지 않는다. M1/M2에 검사할 대상이 없었다는 사실은 작업 성공이 아니다.

비용은 입력·캐시 입력·출력 토큰과 도구 호출, 미완료·오류 실행을 포함한다. 시간은 각 실행의 모델 구간 시간과 전체 시험 시간을 구분한다. 가격이나 비용 등급을 추정하지 않는다.

보류 이력 매핑은 별도 합성 엔진 시험으로 확인한다. 역사적 두 번째 사례에 정답 작성자의 보류 문장을 모델의 이전 판단인 것처럼 넣지 않는다. 따라서 이번 33건은 실제 연속 세션에서의 보류 재처리 성능을 측정하지 않는다.

## 실행 범위

v9는 재검토 전용 계획에 `prompt_version="v9"`를 명시해 선택한다. 다른 네 업무를 이 프롬프트로 처리하지 않는다. 일반 통합 프롬프트와 기존 작업 경로는 유지하며 자동 예약은 생성하거나 호출하지 않는다. 전체 업무 묶음 분리·병렬화와 운영 배포는 이번 모델 비교에 포함하지 않는다.

실행기: `benchmarks/abstraction_v9.py`. 비공개 fixture와 결과는 저장소 밖 로컬 작업 폴더에 둔다. 실패한 준비 단계의 복제본은 원인 조사에 남기고, 정상 수집된 시험 복제본만 경로를 검증한 뒤 정리한다.

입력 정돈 예비 점검의 `study/`는 F21 출처에 불필요한 시스템 알림이 남아 있음을 발견해 중단했다. 알림 제외와 원문 위치 보존 시험을 추가한 `study-clean/`에서는 링크 표기 `[[문서명]]`를 read_node용 이름과 혼동하게 만든 입력 계약 오류를 발견했다. F24 Terra가 이 이름의 조회 실패 뒤 실제로 보류했고, 다른 사례에도 불필요한 실패·재조회가 반복됐다. 이를 모델 품질 실패로 합산하지 않는다.

수정 후 입력은 근거 참조 `target`과 도구용 문서 이름 `target_name`을 구별한다. 링크 괄호·별칭·절 좌표를 읽기용 이름에서 제거하되 재검토할 근거 참조와 작업 key는 보존한다. 같은 오류의 회귀 시험을 추가했다. 앞선 지시문·기준·엔진의 해시 일치 사본은 `study-clean/frozen-source/`에 남겼다.

새 `study-final/`에서 전체 33사례를 두 모델에 각각 다시 실행한다. 삭제·이동·보존의 판단 규칙과 사전 행동 분류는 바꾸지 않았다. 입력 오류 수정에 따른 재실행이며, 중단한 결과나 더 유리한 실행을 최종 집계에 섞지 않는다. 이 표본은 최종 엔진의 한 차례 수행 비교이며 모델별 반복 재현성 증거로 쓰지 않는다.
