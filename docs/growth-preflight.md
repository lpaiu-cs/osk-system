# 성장 실행과 포착의 배포 전 점검

2026-09-17 실 인스턴스 점검에서 실행 명령의 버전별 Codex 경로가 사라져 있었고,
정기 성장 작업은 비활성 상태였다. 실행 파일만 확인하는 `growth run --check`를
추가했다. 이 검사는 모델이나 MCP를 시작하지 않는다. 스케줄러 등록도 같은 검사를
먼저 거친다. 별도 API 공급자나 새로운 에이전트 실행기는 추가하지 않는다.

검사 결과의 경로는 심볼릭 링크를 해소하지 않고 절대화한다. `.venv/bin/python`을
시스템 Python으로 바꾸지 않기 위해서다. POSIX의 상대·빈 PATH 항목은 실제 실행
디렉터리인 vault를 기준으로 검색하고, Windows는 호출 프로세스 기준 검색을 유지한다
([Python의 실행 경로 규칙](https://docs.python.org/3/library/subprocess.html#subprocess.Popen)).

## 포착 오류의 근인

Codex native 전사의 `task_complete`에는 성공뿐 아니라 오류 종료가 들어온다.
goal 후속 턴은 일반 UserMessage 이벤트 없이 입력을 싣고, heartbeat는 하네스가
주입한 도구 결과로 시작하며 마지막 텍스트가 비어 있을 수 있다. 실패·중단 뒤
실행도 새 사용자 발화 없이 진행된다. 이들을 모두 '완료 내용 누락'으로 분류하면
종료된 작업의 관측이 증류 원료에 도달하지 못하고 영구 포착 오류로 남는다.

- 오류 종료는 `failed`, 종료 기록 없이 다음 task가 시작된 부분 기록은 `interrupted`로
  보존한다. 작업 성공이나 완전한 원문을 뜻하지 않는다. 열린 EOF 꼬리는 계속 대기한다.
- goal·heartbeat·실패나 중단 뒤 입력 없는 실행은 `native_trigger`로 명시한다. 앞 입력은
  문맥으로만 보존하며 같은 의도의 재개라고 확정하지 않는다. 새로운 사용자 발화로
  만들어내지 않는다.
- task/response의 대화·턴 식별 검사는 유지한다. task_complete 없는 final 텍스트,
  출처를 확인할 수 없는 무입력 실행을 정상 완료로 추정하지 않는다.
- 원문도 사용자 턴도 포착한 적 없는 시작 흔적은 `awaiting_native`로 따로 반환한다.
  상태를 삭제하거나 검토 완료로 바꾸지 않고, 제한된 성장 작업 슬롯에서 제외한다.
  파일 생성이 관측되면 다시 선택한다. 사용자 턴이나 이전 포착이 있던 원본의 소실은
  이 예외에 들어가지 않는다.
- 저장된 native 경로가 사라지면 같은 대화 ID의 기본 전사·보관 디렉터리에서 찾는다.
  후보가 여럿이면 자동 선택하지 않는다. 파일 안의 대화 ID와 기존 raw 접두부까지
  검증한다. 기존에 살아 있는 명시 경로는 유지한다.
- 아직 scope가 정해지지 않은 대화는 명시적으로 고른 안정적인 세션 키로 첫 착지를
  할 수 있다. 그 뒤 일반 cwd 키로 재개해도 같은 대화 ID의 착지만 사용하며, 그 일반
  키를 전역 결속하지 않는다. 다른 대화나 이미 정해진 다른 scope로는 옮기지 않는다.

## 기존 좌표와 검토 증거 보존

이미 저장된 raw의 v1·v2 직렬화는 그 판본으로 바이트를 대조한다. 새 포착은 v3 헤더에
native turn ID를 싣는다. 새 파서가 찾은 과거 턴은 기존 raw 뒤에 추가하므로 옛 번호,
출처 해시, 완료 영수증과 검토 커서를 바꾸지 않는다. 로컬 커서가 유실돼도 raw의
헤더로 append 순서를 복원한다. 내용 불일치 시 옛 codec으로 우회하지 않는다.

따라서 raw 번호 증가를 새로운 활동 또는 자율 성장으로 세면 안 된다. 복구된 과거
원문, 명시 지시 보존, 자동 포착, 후속 Scope/Domain 재사용을 따로 판독한다.

## 검증 결과

정식 `tests/test_regression.py` 수트는 **1567 통과 / 실패 0 / Windows 권한 검사 생략 4**다.
익명 fixture는 실패·빈 heartbeat·중단·커서 유실·구 codec·원문 변조·전사 이동·대화 간
착지 격리를 검사한다. 실 데이터 복제본의 36개 상태 중 원문 미관측 10건은 대기로 남기고,
나머지 26건은 명시 착지 3건을 포함해 모두 오류 없이 재생했다. 기존 466라운드의 번호·해시·
검토 영수증을 유지하고 113라운드를 추가 포착했으며 재시도 추가는 0건이었다.
원료 밖 기존 492개 파일과 일반 세션 키의 결속은 바뀌지 않았다.

실 인스턴스 갱신·재시작·정기 작업 활성화·모델 호출은 이 검증에 포함하지 않는다.
이 수치는 보존 경로의 검증이며 의미적 증류 또는 자율 성장의 성공률이 아니다.

## 한 번의 배포로 묶기

PR63의 참조·조직 검토, PR64의 숨김 raw 저장, 이 포착·실행 수정의 검증을 마친 뒤
정식 릴리스와 인스턴스 갱신을 한 번 수행한다. 엔진 갱신 전까지 실 MCP·sync daemon과
스케줄러 상태를 유지한다. 실제 갱신 시 기존 writer 재시작 경계를 관리하고 raw
이관·구 좌표 해시·구독 로그인·MCP 쓰기·한정 성장 실행을 각각 확인한다.

기존 참조·허브 누락과 의미적 증류 대기는 별도의 데이터 정돈이다. 이에 필요한
노드 변경은 MCP로 수행하며 엔진을 다시 배포하거나 하네스를 재시작할 이유가 아니다.
