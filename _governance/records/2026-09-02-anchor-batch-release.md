# 앵커가 해시를 대신한다 — v3.10.0

## 적용 시 반드시 할 것

**`scope_memory` 계약이 넓어진다.** `edits=[{old_text,new_text},…]`가 쓰기의 기본이다
— 각 앵커는 저장본에 정확히 한 번, 전부 아니면 전무, 상한은 순결과에만, 해시
불요. `text`는 전체 치환으로 남고 `expect_hash`가 여전히 필수다. 둘 다 없이 부르면
읽기(변화 없음). **마지막 줄 앵커엔 `\n`이 없다** — 저장본은 앞뒤 공백을 벗긴
형태라, 훅이 주입한 전문에서 그대로 복사하면 맞고 끝에 개행을 붙이면 빗나간다.

**`update_node`에도 같은 계약이다.** `old_text`/`new_text`로 본문을 부분 편집하고
해시를 요구하지 않는다. `body`는 전문 치환으로 남는다.

**케이던스 훅이 바뀌었다.** 9턴에 전문·해시·여유를 주입하고 "다음 도구 호출에
함께 실어라"를 지시한다. 15턴까지 갱신이 없으면 다시 주입하되 단독 턴을 허용한다.
훅이 이제 엔진을 import하므로 등록된 인터프리터(인스턴스 `.venv`)에 엔진 의존이
있어야 한다 — 세션 시작 훅과 같은 조건이다. 갱신 뒤 **MCP 서버를 재기동**하라;
낡은 엔진은 쓰기를 거부한다.

**이 판의 확인법**: `git show v3.10.0:_governance/_engine/osk/scope_memory.py |
grep -c OVERFLOW_STOP` — **v3.9.1은 0, v3.10.0은 2**다. 파일 목록이 아니라 내용을
대조한다(v3.9.1 사료).

## 무엇을 고쳤나

세 커밋이다. 근거와 실측은 결정기록 `2026-09-02-anchor-batch-scope-memory.md`에
있고, 여기는 무엇이 실렸는지만 적는다.

1. **`update_node` 앵커 편집** (`920edf9`). §6-2 4항이 이미 "부분 변경에는 해시를
   요구하지 않는다"로 갈라 둔 자리라 조문 개정이 없었다. 상주 스키마 예산은
   응답·거부문이 이미 그때 말해 주는 문장 넷을 걷어 맞췄다(4자 → 40자 여유).
2. **§9-2 4항 개정** (`301192e`). 부분 연산 금지의 근거("무엇을 버릴지 엔진이
   모른다")는 지키고 결론만 고쳤다 — 버리는 결정은 호출자가 같은 호출 안에서.
   연속 3회 거부 시 재시도 지시를 거둔다. 5항에 앵커 불일치를 전문 싣는 거부로
   추가. v3.9.x 때 조문에 넣었던 실측 문장은 사료로 뺐다.
3. **`scope_memory` 앵커 일괄 + 훅** (`1c92786`). 엔진은 파일을 파싱하지 않는다 —
   원소는 호출자가 앵커로 그때 정한다. 훅은 9턴 동승·15턴 단독·갱신 시 리셋.
   표면 예산은 다시 120자를 넘겨 중복 넷을 더 걷었다(7,452/7,500).

마지막 뮤턴트는 **처음 시험이 못 잡았다.** 리셋 유무는 16턴이 아니라 24턴에서
갈리므로(리셋되면 9턴째 재주입, 안 되면 침묵) 시험을 그 자리까지 밀어 잡았다.
통과 건수는 근거가 아니다 — 살아남은 뮤턴트가 시험의 구멍이다.

시험이 잡은 내 실수 둘: 거부 헤드라인은 `violations`에 안 실린다(안내문만),
그리고 `canon()`이 끝 개행을 벗긴다. 둘 다 시험 쪽이 틀렸고 엔진은 맞았다 —
후자는 호출자도 밟을 자리라 「적용 시」에 올렸다.

## 남은 것

1. **판정은 재측정이다.** 통합 단독률(개정 전 100%)·상한 초과 재시도(104턴/14일)·
   거부 에피소드 중 증류(7%). `osk_turn_ledger.py`가 그대로 잰다. 훅의 문구 부분은
   증거 등급이 가장 낮다 — 되는지는 재 봐야 안다.
2. **연속 거부 계수는 프로세스 안**이다. CLI 경로(`osk sm write`)는 매번 새
   프로세스라 세지 못한다. 8연속 거부는 MCP 경로에서 났으므로 지금은 충분하다.
3. **Claude Code식 색인/내용 분리**는 넣지 않았다. scope 기억이 무엇인지를 바꾸는
   일이라 따로 다룬다.
