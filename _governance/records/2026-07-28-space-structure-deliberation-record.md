# 2026-07-28 — osk-system 재설계 심의 기록: 공간(Space) 구조의 채택

> 이 기록은 2026-07 하순 검토 세션(독립 검토자 Claude + GPT 교차 검토 + 14-에이전트 레드팀)의
> 심의 경과와 사용자 판정을 보존한다. 판정의 주체는 사용자이고, 본 문서는 초안이다 —
> 배치(사설 vault 결정 기록 또는 신체제 기록부)와 확정은 사용자·워커가 수행한다.
> 「되돌린 갈래도 남긴다」(구 mechanism ADR 원칙)에 따라 기각의 계보를 함께 기록한다.

## 1. 최종 판정 (2026-07-28, 사용자)

1. **수직 계층화 폐기.** 공간 사이에 위계·서열·승격 사다리를 두지 않는다.
2. **명칭: Layer → Space (임시).** 세 공간명도 변경 가능한 임시 명칭이다.
3. **공간 분리 유지 — 단일 저장 그래프 구조 기각.** 참조는 공간을 넘어 자유이므로
   그래프의 연결성은 하나이되, 저장·규율·경계의 관할은 셋이다.
   **근거(사용자):** 공간화의 이점이 없더라도 추후 포기(병합)하는 비용은 싸다.
   그러나 단일 구조를 나중에 분리하는 비용은 비싸다 — 옵션 보존.
4. **3공간 정의:**
   - **Observation space** — scope에 한정된 작업 기억 및 이해.
   - **Sense space** — 각 scope를 벗어나 전역적으로 기억될 기억 및 이해.
     범 scope 연결이 가능해야 하므로 sense 단위로 응집.
   - **User model space** — 사용자의 선호·정보·판단·개인적 기억, 사용자에 대한
     이해 전반의 기록 및 이해.
5. **「동등 규칙」의 해명(사용자):** 각 공간의 노드가 모두 기억·이해로서 지식
   노드의 성격을 가지며 공간 간 위계가 폐지된다는 뜻이다 — 생애 규칙의 균일을
   뜻하지 않는다. (공통 envelope + 역할별 생애 규칙과 양립.)
6. **토론 세션과 판정의 문서화 지시.** (본 기록이 그 이행이다.)

### 판정의 구조적 독해

- 공간 축은 인식 종류(기록/모델)도 인식 성숙도(구 O/S/K)도 아닌 **관할**
  (도달 범위·주제)이다: scope 한정 / 전역 / 사용자 주제.
- 세 공간 모두 「기억 및 이해」를 담으므로 **역할 축(기억=기록 / 이해=모델)은
  공간과 직교**한다.
- 전역 내구 이해를 위한 별도 공간(구 K)은 없다 — Sense space의 거주자다.
- User model space는 사설 데이터의 핵으로서 공개·사설 물리 경계와 자연 일치한다.

## 2. 경위 — 이 심의가 여기 온 길

1. **발단.** G1(Predicate Edge의 응집 반영) 검토 세션 중 사용자가 근본 회의를
   제기 — 「지식은 인터넷에서 모두 찾을 수 있다. 왜 따로 저장하는가?」 회상 결과
   같은 회의가 2026-07-06 재헌법화의 창립 사건이었음이 확인됨(「이해 미통과
   저장은 인지가 아니라 적재다」).
2. **목적의 전환.** 체계의 목적을 「사용자가 읽는 second brain」에서 **「사용자를
   아는 에이전트의 장기기억」**(1차 독자 = 에이전트)으로 재정의. 사용자 판정:
   「나는 똑똑한 맞춤형 비서를 만들어야 한다.」
3. **사용자상 중심 재설계.** 사용자상(使用者像) 정의 확정, 서명=자기표상의 가결
   의미론, 증거 추적 완화(C), 검색 범위(D) 판정.
4. **투영 모델과 그 한계.** S 비소모·K=가결된 한 문장 명제 구조 채택 후,
   「K가 S를 참조하며 중심부·주변부 가중이 역전된다」는 문제로 사용자가 K의
   존재 가치에 회의 — 구 3층 복원 검토 → K 폐지 + 사용자상 층 → 인식층 2 +
   권위층 1 → 단일 flat graph + typed modular(GPT 제안) 순으로 후보가 진화.
5. **레드팀.** 비준 직전 사용자 지시로 14-에이전트 레드팀(opus 2·sonnet 3·
   haiku 1·fable 1 + fable 검증관 7) 수행 — 발견 49건, CONFIRMED 14·PARTIAL 28·
   ADDRESSED 5·WRONG 2. 병행한 GPT 정밀 판정(2개 모델 라인, 3개 관점)도 동일
   결론: 「flat + 완전 동등 규칙은 비준 불가. 폐기할 것은 층이 아니라 높이
   은유다.」
6. **공간 판정(본 기록 §1).** 사용자가 수직 위계 폐기 + 공간 분리 유지로 확정.

## 4. 이 사이클에서 확정된 제도 (공간 구조와 직교 — 신 체제로 이식)

1. **행동 권한의 이원화** — 모든 가결 항목은 전제 사용을 허가하고, 행동 권한은
   그것을 명시한 위임·제약형 항목만 부여. 회수는 사용자 지시로 즉시 효력,
   기록 후속. 「인식은 강등된 채 열리고, 권한은 보류된 채 닫힌다.」
2. **불확실성의 보수 해소 원칙** — 위임 불명→행동 않음, 금지 불명→금지 유지,
   의무 불명→보류, 판정 불능→사용자 확인. (구 13조 3항 「모호하면 승인제」의 후계)
3. **권한 사전 검사** — 위임·제약은 의미 검색이 아니라 행동 계획 전 결정론적
   전수 조회(3값: 적용/비적용/불명, 불명≠비적용, fail-closed). 검사 대상 =
   활성 권한 집합(현재 명시 지시 + 작업 유효 지시 + 가결된 지속 위임·제약).
4. **즉시 효력과 지속의 분리** — 직접 지시는 발화 즉시 원문의 보수적 독해로
   유효(주권), 가결이 부여하는 것은 장래 세션 지속성. 적용 봉투(행동·범위·
   효과·조건·기간·우선순위)는 상정 시점 완성, 원문에서 결정되지 않는 필드는
   에이전트가 임의 기입 불가 — 보충분은 가결 diff에 표시.
5. **제한 완화는 사용자의 명시적 발화로만.** 생발화가 가결 정본과 실제 모순이면
   발화를 따르되 재심 신호로 입건.
6. **사건부 개혁** — 충돌 사건은 노드에 사건별 상태(docketed/preserved, 부재=
   심의없음)로 표면화(신뢰 라벨이 아니라 사건부의 투영). 사용자 방치 시 사건부
   에이전트가 자체 심의 종결 가능(기각/보존/미서명 개정+replaces) — 서명·가결의
   생성·회수는 불가, 위임·제약 사건은 사용자 전속. 기판력 차등(에이전트 종결은
   약한 기판력), 비준·번복은 사건 유형별 판례 지지력으로 축적. 인식 축에서
   입건은 봉인을 깨고(잠정 사용 지속), 권위 축에서 입건은 가결 기록을 소거하지
   않으며 효력은 유형별 보수 규칙.
7. **자기강화 금지** — 에이전트가 사용자 표상을 근거로 취한 행동이 유발한
   암묵 반응은 그 표상의 독립 증거가 아니다. 맥락을 아는 사용자의 명시적
   확인·정정은 직접 증거다.
8. **append-only 권위 원장** — 가결·회수·대체는 안정 ID·가결 상태 해시·적용
   봉투·선행 사건 참조를 가진 마크다운 사건으로 기록, 현재 권위 = 사건 재생,
   과거 사건 불수정, 내용 변경 시 가결 자동 이전 없음. (+레드팀 처방: 적용
   규칙 버전 필드 필수 — §8.5 비소급의 승계)
9. **검색 계약의 분리** — 작업 검색(에이전트, 전역, 미서명 무강등 — 서명은
   회수가 아니라 의존에 작용) / 열람 검색(사용자 대면, 미확인 표기 의무) /
   권한 사전 검사(랭킹 금지). 공간 구조 아래 기본 범위: 전역 공간(Sense·User
   model) + 현재 scope의 Observation, 타 scope는 scope_index 회상 라우팅.
10. **링크 평면 분리** — 탐색 링크와 근거·의존 배선을 구별, 중심성·전파는
    의존만 산입. (사용자의 2026-07-02 판례 「링크는 자유, 엣지는 게이트」의 복권)
11. **파일 정본주의** — 역할·출처·근거 링크·계보·저작·pin·명명·권위 원장은
    파일 정본, 뷰·랭킹·중심성·계산 소속은 재계산 가능 파생물. 엔진 없는
    가독·복구, 파일 이동은 의미·권위 불변.
12. **증거 추적 완화(C)** — raw 원인추적에 비집착, 오류는 충돌 사건화로 처리,
    예외적 보존은 선별 아카이브. 「장기 역사 보존은 주요 업무가 아니다.」
13. **이중 루프** — 내구선 아래 scope 세션 기록의 국소 귀납 → 펌프(보고·증류·
    상정) → 내구선 위 전역 루프. 지속성 경계(작업 한정 지시는 등재 없이 즉시
    유효).
14. **검증기 규율** — 사양·fixture는 선행 가능, 자동 집행은 검증기 활성화 없이
    불가, 실패는 fail-closed, 수동 복구 경로 상존.

## 6. 열린 질문 (다음 판정 라운드)

1. **공간 간 이동의 형식** — 같은 주장 그대로면 동일 ID 재분류(이동+계보),
   재서술이 필요하면 새 노드+derived-from. 기준 필요(구 정련/교체 갈림의 공간판).
2. **역할 축(기억/이해)의 명문화** — 공간과 직교임을 조문으로 확정할지.
3. **Observation space 내부의 내구선** — 세션 기록(비노드)과 노드의 경계.

**구조·제도 (구 열린 질문 3~8의 해소)**

9. **미서명 중심성 번복 가결**: 개정 비용(dependency_centrality)은 서명과
   무관하게 유효한 typed dependency로 계산한다(구 11조 3항의 명시적 번복).
   서명·가결은 별도 권위 축 — 미서명 노드도 구조적으로 중심일 수 있으나
   행동 권한의 근거는 될 수 없고, 열람 검색의 미확인 표기는 유지된다.
   자유 탐색 링크는 비산입, 공간별 중심성 + 교차 다리는 별도 항목.
10. **휴면 폐지 가결**: `dormant` 생애 상태를 두지 않는다. 헌법에는 「보존과
    주의를 분리한다」·「주의 표면은 유한하다」 두 문장만. 노출은 랭킹(최신성·
    관련성·중심성·locality)으로 연속 조절, cold tier는 파생물, 시간 경과만으로
    삭제·불신·권위 박탈 없음, 명시 검색은 cold·raw까지 도달. **pin만** 사용자의
    지속적 주의 지시로 정본 기록하되, 노드 frontmatter가 아니라 별도 pin
    registry/사용자 사건으로.
11. **브리핑 4채널 가결**: 즉시 알림 / 주간 판정 후보 / 주간 정보 요약 /
    무손실 전체 목록. **즉시 알림도 처리 의무를 만들지 않는다** — fail-closed
    사건의 통지는 행동이 이미 보수적으로 정지된 상태의 알림이므로 의무가
    아니라 해제 옵션이다. 승격 후보 항목은 폐지(필요시 상정 후보로 개칭).
12. **기록 대 기록 불일치 채널 가결**: record↔record 불일치는 충돌 심의가
    아니라 재관측·출처 확인 채널로. contradicts는 모델 간 한정. 기록은 사후
    이론에 맞게 개작하지 않는다. 실제 관측이 불일치하면 둘 다 보존하고,
    해소 전에는 이를 쓰는 모델의 확정적 적용을 보수적으로 제한.
13. **A3(에이전트 자체 종결) 잠정 가결** — B.3의 축자 문안으로. 단 **사건
    생애주기 정립 시 재론 예약.**
14. **명칭 가결**: 총칭 **Space**(Memory Space) / **Scope Space** /
    **Sense Space** / **User Model Space**. Workbench는 Space가 아니고,
    사건부·원장·통치 문서는 공간 밖 제도 기록. 체계 이름 **osk-system은
    역사적 고유명사로 당분간 유지** — 재명명은 첫 정식 릴리스 후 별도 원소.

### B.3 A3 축자 문안 (잠정 가결본)

1. **발동**: 입건된 사건이 ①상당 기간 경과 ②진행 중 작업의 차단 ③대기열
   과적 중 하나에 해당할 때. 사용자의 무응답 횟수는 발동 조건이 아니며,
   명시적 보류(defer)가 걸린 사건은 개시하지 않는다.
2. **대상**: 미가결 모델 사이의 충돌만. 가결 항목이 당사자인 사건, 위임·제약,
   사용자 저작의 의미 변경, 영구 삭제는 사용자 전속.
