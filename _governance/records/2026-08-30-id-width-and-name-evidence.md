# 담보를 폭으로, 근거를 제목으로 — v3.7.3

## 적용 시 반드시 할 것

**`osk`라는 셸 명령은 없다.** 그렇게 치면 Windows 내장 화상 키보드
(`C:\Windows\System32\osk.exe`)가 뜬다. 호출은 모듈로 한다:

```powershell
$env:PYTHONPATH="_governance\_engine"
& <venv>\python.exe -m osk.release --version vX.Y.Z --apply   # 정본 cwd, 대화형 전속
& <venv>\python.exe -m osk.update --apply                     # 인스턴스 cwd
```

**데몬은 프로세스째 멈춘다.** 예약 작업 이름은 **`osk-sync-daemon`**이고,
`Stop-ScheduledTask`만으로는 손자 `pythonw`가 살아남아 싱글턴 잠금을 쥔다.

```powershell
Get-CimInstance Win32_Process -Filter "Name LIKE 'python%'" |
  Where-Object { $_.CommandLine -like '*sync_daemon*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

프로세스를 셀 때 **하나를 둘로 세지 않는다** — venv의 `python.exe`/`pythonw.exe`
는 런처 스텁이라 데몬 하나가 두 프로세스로 보인다.

**이 판은 MCP 서버 재기동이 필수다.** 이관(아래)이 노드를 고치는 작업인데,
판본 관문이 낡은 프로세스의 쓰기를 거부한다. 실제로 이 판을 만드는 중에
scope 기억 갱신이 그 관문에 막혔다 — 관문이 제 일을 했다.

## 무엇을 바꿨나

### §2 1항 — 담보가 검증에서 폭으로

무작위부를 4자에서 **8자**로 넓히고, 생성 시 전수 대조를 폐지했다. 철회한
문장은 이것이다:

> 부여 시 기존 `id` 전수와 대조하여 중복이면 무작위부를 재생성한다 —
> 유일성의 담보는 길이가 아니라 이 검증이다.

앞 11자(`YYMMDD-ssss`)가 결정적이므로 **충돌은 같은 초 안에서만** 일어난다.
4자는 2^20.7이라 같은 초 183건에서 충돌이 1%였고, 실 vault는 이미 한 초에
41개를 만든 적이 있다. 8자는 2^41.4 — 같은 초에 23만 건까지 1% 미만이다.

**싸게 검사하는 길은 없었다.** "오늘 만든 것만 대조하자"는 옳은 착상이지만
어느 것이 오늘 것인지가 파일 **안에** 있어 성립하지 않고, 그 읽기가 정확히
문제의 6.4초다. 파일 mtime은 clone·복원이 덮어써 가장 필요할 때 가장 틀린다.

정확히 적자면 8자는 충돌을 **구성적으로 불가능하게 만들지 않는다** —
"독립·균등 난수 가정에서 운영상 무시할 만큼 작다"가 맞다. 그리고 중복 id의
실제 발생원은 id 생성이 아니라 **파일 복제**(옵시디언 "사본 만들기"·백업
복원·병합의 수동 해결)이며 그 경로는 `new_node_id`를 거치지 않는다. 전수
대조는 그것을 막지 못했다. 그 경로는 v3.7.2의 중복 거부가 막는다.

### §8 2항 — 근거가 id에서 제목으로

노드 근거를 id 맨값에서 **제목 위키링크**로 뒤집었다. 현행 근거였던

> 경로·이름은 상태라 ①이동·②개명에 끊어지고, ③같은 이름이 재사용되면 다른
> 노드를 가리킨다

를 셋 다 확인한 결과:

- **① 이동 — 이름에는 거짓이다.** `move_node`는 디렉토리만 바꾸고
  (`target = dest_dir / path.name`) 이름 색인은 경로와 무관하다. 정작
  **끊어지는 것은 경로형**이다(`resolve`의 `/` 갈래는 그 자리에 파일이 없으면
  dangling). ①과 ③이 서로를 무효화하고 있었다.
- **② 개명 — 표면이 없었다.** 그리고 실제 개명 표면인 옵시디언은 개명 시
  frontmatter 위키링크를 **함께 재작성한다**(실기 확인).
- **③ 재사용 — 완화책이 이미 있었다.** 다만 경로형이 아니라 전역 유일한
  제목이다. 경로형은 `contract.target_stem`이 이름형과 **같은 키로 접어**
  `resolve` 밖에서는 구별되지도 않는다.

그래서 노드 근거에 **경로 표기를 금하고 제목을 정본**으로 두었다. 구형 id
표기는 계속 해석한다. **§2 3항("동일성의 정본은 `id`")은 손대지 않았다** —
바뀌는 것은 참조 표기이지 동일성이 아니며, 대장·서명·사건부는 그대로 id로
남는다. 옵시디언에서 근거가 백링크·그래프에 살아나는 것은 덤이다.

## 철회한 권고 하나

파손 파일에 대한 생성 관문을 **제자리에 다시 세우려 했으나 무산됐다.**

그 관문은 `_existing_ids` 안에 있었고 근거는 id였다. 근거는 이 판이 지웠지만
관문 자체는 다른 일 — 파손이 오래 남지 못하게 하는 **강제 함수** — 을 하고
있었다. 그런데 "파손이 있는가"는 `idx.broken`을 물어야 알고 그것이 전수
판독을 강제한다. **관문 하나에 이 판이 없앤 값을 매 생성 도로 내는 셈이다.**

대신 알림에 기댄다. `overview`가 이미 `broken`을 싣고, 그 자리에서는 색인이
이미 파싱돼 있어 **무료**이며, 세션 시작마다 돈다. 이 맞바꿈이 사고가 아니라
판단이었음을 `test_broken_is_reported_not_gated`가 고정한다.

**관문을 되살리려면 조건은 하나다 — 전수 판독이 이미 일어난 자리에 둘 것.**
쓰기 통로는 그런 자리가 아니다.

## 실측 — 25,000 노드, 한 프로세스

| | v3.7.2 | v3.7.3 |
|---|---|---|
| `create_node` 엣지 없음 | 4,004 ms | **508 ms** |
| `create_node` 제목형 근거 | 5,432 ms | **607 ms** |
| `create_node` 구형 id 근거 | 5,432 ms | 4,543 ms |
| **전역 잠금 보유** | **3,463 ms** | **398 ms** |

v3.7.1이 1순위로 적은 것이 *"지연이 아니라 직렬화다"*였다. 그 3.5초가 0.4초가
됐다. 구형 id 근거만 여전히 4.5초인 것은 **의도한 기울기**다 — 옛 표기는
느리고 새 표기는 빠르며, 이관을 미룰수록 값을 낸다.

## 시험

구 규범을 encode한 시험 8건을 뒤집었다. 셋이 새 계약을 고정한다.

- **`create_node`는 전수 판독을 부르지 않는다** — 이전엔 `== 1`을 단언했다.
  성능 계약이 시험에 박혔다.
- 제목 표기는 위반이 아니고 **경로 표기가 위반**이다.
- 파손이 있어도 생성은 되고 `overview`가 알린다 — 맞바꿈의 명시.

그리고 `test_id_width_and_discriminator`가 8자 폭과 함께, `ID_RE`가
3·5·9·12자·대문자·평범한 제목을 id로 읽지 않는지 고정한다. `ID_RE`는 유효성
검사가 아니라 **"id인가 이름인가"의 판별자**이고 여섯 자리에서 쓰이므로,
넓히는 폭이 4|8 두 값에 머무는지가 계약이다.

수트 885 통과 / 기지 실패 5.

## 남은 것 — 이관

이 판은 **표기 규칙만 바꿨고 기존 데이터는 그대로다.** 실 vault에 남은 구형
표기:

- `derived-from` id 표기 — **78노드 / 125간선**
- 본문 Link id 표기 — **5노드 / 15간선**

노드는 MCP 도구로만 고칠 수 있으므로 이관은 **릴리스·갱신·서버 재기동 뒤**다.
이관이 끝나야 `resolve`의 id 갈래가 식고, 그때 비로소 구형 표기를 거부할지
(v3.7.4) 판단할 수 있다.

이관은 되돌리기가 비싸다(125간선을 도로 옮겨야 한다). **한 노드에 먼저 적용해
저장 표기·백링크·검증기를 확인한 뒤** 나머지를 돌린다.

## v3.7.4 이후의 재료 (3자 독립 검토가 지목)

1. **쓰기 응답의 주 손잡이를 이름으로.** id 핸들 `update_node`가 이름의 10배다
   (486 대 5,065 ms). 응답이 id를 돌려주니 에이전트가 id를 손잡이로 잡는다.
   이것이 id→이름 지도를 **지배한다** — 새 파생 구조 없이 같은 이득이다.
2. **Searcher 결합·중복 제거.** `overview`·`read_node`도 `_s()`를 부르므로
   "검색 안 하는 서버는 검색 메모리를 안 잡는다"가 거짓이다. `_s()`는 새
   Searcher를 다 짓고서야 옛 것을 놓아 재적재 창에서 1.5배를 쥔다.
3. **읽기 통로의 규모.** 어떤 쓰기든 지문을 무효화하므로 각 프로세스가 다음
   읽기에서 독립적으로 전수 판독을 문다 — 잠금과 달리 **곱해진다.**
4. **동기화 데몬의 잠금 보유.** `sync_daemon._once`가 같은
   `osk-mutation.lock`을 쥔 채 git pull/push의 네트워크 왕복을 지난다(최악
   ~120초). 잠금 입도를 쪼개도 최악값은 안 움직인다.
5. **id→이름 지도는 도입하지 않는다.** 점 검증은 존재를 증명하고 유일성을
   증명하지 못한다 — 3자가 각자 반례를 지어 왔다.
