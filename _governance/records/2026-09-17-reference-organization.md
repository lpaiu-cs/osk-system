# 저장 뒤에도 참조와 조직은 자라야 한다

2026-09-17 사용자가 근인 수정 후 운영 정리와 독립 에이전트 백테스트를 승인했다. 시행령 §3 1항의 같은 Scope 내부 비고정 배치 위임과 Mechanism §9-4를 구현한 근거다. 이 승인은 정본 릴리스 선언이나 인스턴스 갱신 완료를 뜻하지 않는다.

## 근인과 선택

노드 저장 응답은 본문의 미해석 Link를 알려도 PE와 원료 항해를 함께 다루지 않았고, 그 알림을 다음 통합·성장 실행의 작업으로 이어 주지 않았다. 외부 레포 문서를 vault 상대주소로 기록하거나 존재하지 않는 제목을 인용하면 자료는 보존되지만 관계가 자라지 않는다. 쓰기·전역 점검·조직 검토가 같은 참조 판독을 사용하게 한다.

원료의 Markdown과 내부 링크를 Obsidian이 그리는 것은 지식 노드 승격과 다르다. raw를 지우거나 가짜 노드로 감싸지 않고, 지식 Space와 계약 식별 필드로 그래프를 투영한다. 원료의 실제 보존·근거 좌표와 그래프 표시를 별개로 검사한다.

같은 Scope 내부 정돈은 기존 통합과 성장 실행에 조건부로 싣는다. 별도 실행기·모델 API·자동 개수 기준을 만들지 않는다. 기존 의미상 입구를 읽고 실제 하위 군집과 허브가 필요한지 판단한다. 결과를 저장했다고 현재 조직까지 완료됐다고 세지 않는다.

역사적 증류 증거를 경로에만 묶으면 같은 ID·같은 본문의 정상 이동도 실패가 된다. 역사 기록은 그대로 두고 ID·내용·최상위 소속으로 보존을 검사하며, 현재 허브의 항해 연결은 별도로 판정한다. 여러 파일 이동의 I/O 중단은 원자적 롤백이라고 주장하지 않고, 이동 의도를 남겨 현재 ID 위치에서 이어간다.

## 반증과 한계

독립 반증에서 빈 본문의 완료, 없는 raw 라운드의 PE, 삭제 ID의 다음 큐 탈락, 조직 오류가 raw 안내를 가리는 회귀, ID형 허브 Link의 거짓 미완료를 재현했다. 공통 경계 수정 후 독립 반례 검사 10건이 통과했다. 정식 회귀 러너는 소스 변경 없이 1,566 통과·0 실패·Windows POSIX 권한 검사 4개 생략을 확인했다.

처음 전체 수트를 돌리며 엔진 파일을 수정해 epoch fence가 낸 결과는 유효한 회귀 판정으로 쓰지 않았다. 고정 실행의 단일 안내문 CLI 표 누락도 실제 문서·파서 대조로 고치고 전체 수트를 다시 돌렸다.

기계 검사는 ID·비어 있지 않은 본문·실재하는 선택 출처·현재 배선을 확인한다. 의미의 타당성이나 분화의 적절성은 증명하지 않는다. 사용자 지시로 수행한 정리·실험을 자연 발생한 훅 동작으로 계산하지 않는다. raw→Scope의 저장과 다음 독립 세션이 갱신 Scope를 실제로 읽어 Domain에 반영하는 것을 나눠 검증한다.

## 비용과 보류

조직 판독은 변경된 Scope의 지식 목록을 전달하고 실제 본문을 추가로 읽으므로 비용이 든다. 동일 완료 snapshot은 반복하지 않으며, 성장 실행에서 중복되던 조직 목록은 한 번만 싣는다. 읽어야 할 정보가 너무 많으면 deferred와 남은 작업을 유지한다. 이 문서의 구현 검사만으로 검색 효율·토큰 절감·정기 자율 운영을 입증했다고 보고하지 않는다.

실행·복구 명령은 [운용 안내](../../docs/GROWTH-INTEGRITY.md)에 둔다. 보호영역·pin·최상위 경계와 사용자의 정본 릴리스 선언 권위는 유지한다.

## 승인된 운영 정리

대상 Scope의 기존 60개 ID를 보존하면서 57개 노드를 본문 바이트 그대로 재배치하고, 얇은 허브 5개와 기존 결정 노드의 허브 재사용으로 루트와 하위 허브 6개를 구성했다. 미해석 참조 9건은 작성 당시의 외부 문서 상대주소와 잘못된 내부 제목이었다. 외부 문서는 실제 저장소 revision에 고정된 주소로, 내부 참조는 대상 본문을 확인한 제목으로 고쳤다. 원료 항해 Link 2건은 실제 라운드를 읽고 근거 좌표로 옮겼다. 미해석 참조·원료 항해·지역 허브 미완료는 최종 검사에서 0이며 원료 13개는 바이트 동일하다. 모든 그래프 변경은 MCP로 수행했다.

독립 전수 판독자는 원문과 이동 결과, 입구 변경, 새 허브를 대조했다. 허브 요약의 단어 하나가 다른 사건에 잘못 귀속된 것을 찾아 수정한 뒤 재확인했다. 파일 보존과 배선 통과만으로 의미 정확성을 보장할 수 없다는 반례도 함께 남긴다. 일반 입구의 유용한 상위 Link를 유지하려고 작은 허브 하나를 추가한 비용을 받아들였다.

Obsidian은 설정 파일의 백업·변경·되읽기까지 확인했으며 실제 앱 화면은 확인하지 않았다. 구버전과 수정 버전의 지식 인덱스·성장 후보는 모두 원료를 이미 제외했다. 따라서 Markdown 원료가 그래프 화면에서 노드처럼 보이는 현상을 엔진의 Domain 후보 혼입으로 확대하지 않는다. 설치된 엔진은 v3.14.1이며 새 조직 훅의 운영 배포와 정기 자율 성장은 별도 검증 대상이다.

## 고정 자료의 독립 에이전트 백테스트

과거 cutoff의 Scope 60개·Domain 7개와 이후 원료의 공개 라운드 3개(14,315자), 사실·한계 보존 루브릭을 실행 전에 고정했다. 각 조건에 새 에이전트 2개씩 총 4개를 실행했다. 첫 단계는 raw→Scope, 다음 단계는 변경된 비raw Scope와 기존 Domain만 받고 Scope→Domain을 수행했다. 실행은 구독 에이전트와 실제 MCP 연결을 사용하며 별도 모델 API를 호출하지 않았다. 평가자는 조건 이름을 가리고 원료·기준선·저장본·실제 전달 본문을 대조했다.

두 조건 모두 사건 노드 2개를 만들고 다음 독립 세션에서 기존 Domain 지식 2개를 갱신했다. 수정 조건은 하위 허브 1개 생성·동일 ID 이동 2개와 Domain 허브 갱신도 수행했다. 원료 7개는 조건별로 바이트 동일했다. 다음 세션이 변경된 Scope 본문을 실제로 받은 hash와 시각을 대조해 첫 Domain 쓰기 전에 구버전 5개·수정 버전 6개를 읽었음을 확인했다. 허브 개수 증가는 의미 품질의 점수로 쓰지 않는다.

독립 의미 채점에서 원료 보존·분리, 새 사실과 한계의 Scope 보존, 의미 있는 연결, 다음 세션의 Scope 소비, Domain 의미 증가는 두 조건 모두 통과했다. 기존 결론의 정정은 구버전 부분 통과·수정 조건 통과다. 구버전은 관련 결정문에 오래된 현재형 결론을 남겼고 수정 조건은 그 문서까지 정정했다. 1단계 판정은 2단계 판독 전에 동결했으며 후속 성공으로 앞 단계의 결함을 지우지 않았다.

Domain의 유용한 증가분은 재생에 주입한 결정과 자체 생성 결정의 구분, 검출 능력과 내부 기전 식별·미관측 분기의 구분, 완결/중단 실행과 선별/로그 분모를 함께 고정하는 검증 조건이었다. 단순 사례·출처 추가에는 점수를 주지 않았다. 실제 전달·재조회 42건의 본문과 해시가 일치했고 기존 ID·출처·미확정 한계를 보존했다. 세션 격리는 제공된 실행 지침과 전달 기록에 근거하며 운영 시스템 전체의 접근 부재를 별도로 감사했다고 주장하지 않는다.

이 판정은 격리된 명시적 작업에서 raw→Scope→다음 독립 세션의 Domain으로 유용한 지식이 이어졌다는 근거다. 수정 조건의 의미 있는 하위허브 형성과 관련 결론 정정도 관측했다. 조건별 1회 실행의 인과적 우월성·일반 성공률이나 자연 자율 운영의 증거로 확대하지 않는다.

수정 조건은 남은 지역 허브 미직결 40건과 미해석 참조 11건을 완료로 숨기지 않고 deferred로 접수했다. 격리 실험에서 허용되지 않은 외부 문서나 현재 운영 결과로 과거 자료를 보충하지 않았다. 전체 정돈 완료가 아니라, 완료한 부분과 다음 작업을 구분해 남긴 관측이다.

실험 transport의 임시 파일 위치·출처 hash 접두어·scope_memory 저장 경로 오류를 두 조건에 같은 원칙으로 수정하고 실패 예산을 보정했다. 엔진·원료·루브릭은 바꾸지 않았다. 보호영역 fixture는 격리 경계의 nul 쓰기 차단으로 실패했으므로 이 실험에서 전체 validator가 통과했다고 주장하지 않는다. 최종 제품 소스의 회귀 판정은 위 정식 러너 결과다.

수정 조건의 실험 엔진은 `66586bd`에서 고정했다. 이후 최종 제품의 legacy move_node 실패 전달 어댑터를 고쳤으며 공개 MCP move_nodes 실험 경로는 변경되지 않았다. 최종 제품은 별도의 고정 소스 전체 회귀로 검사했다.

두 단계의 실제 비캐시 입력은 구버전 283,556토큰, 수정 버전 378,677토큰으로 수정 조건이 33.5% 더 많았다. 출력은 각각 37,969·48,012토큰이다. 캐시 입력을 별도로 계수했고 추론 토큰을 출력에 중복 합산하지 않았다. 작업량과 transport 중단이 다른 조건별 1회 실행이므로 인과적 효율 수치·일반 성공률로 확대하지 않는다. 지식 연속성에 비용을 지불한 관측이며 토큰 절감 증거는 아니다. 조직 판독은 기존 통합·성장 주기에 조건부로 싣고 매 턴 강제하지 않는다.
