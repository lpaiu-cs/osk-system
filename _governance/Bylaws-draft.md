# knowledge-vault 시행령 (Bylaws) — 개정 초안

> 헌법([[Constitution]], 2026-07-19 개정판) 아래의 운영 기본값이다. 헌법이
> 무엇과 왜를 정하면, 시행령은 어떻게를 정한다. 개정은 헌법보다 가볍다 —
> 사용자 지시 또는 판례 축적(§13)으로 바뀐다. 이 문서의 어떤 조항도 헌법을
> 넘어서지 못한다.
> 비준 시 구 [[Bylaws]](2026-07-06)를 supersede한다. 에이전트 저작 초안이며,
> [미결] 표기는 사용자 판정 대기 항목이다.

## §1. 어휘

1. **용어 원칙**: CS·인지과학에서 원어가 통용되는 개념은 원어로, 자연스러운 관용
   한국어가 있으면 한국어로 쓴다. 번역투 조어는 금지한다.
2. **용어 이행 표** — 2026-07-17 용어 개정 이전의 문서(구 시행령, 결정 기록,
   분류 전표)를 읽을 때 적용한다:

   | 구 문서의 용어 | 현행 용어 |
   |---|---|
   | 스코프, Scope Layer | **Synthesis**, Sensemaking Layer |
   | 관측 클러스터 | **Scope** |
   | (Knowledge의) 클러스터 | **Domain** |
   | Observation→Sensemaking 증류, Synthesis 형성 | **응집** |
   | 작업대 | Workbench |
   | 술어 엣지 | Predicate Edge |
   | 불변식 | (범주 폐지) → 조문 + §14 검증 제약 |

3. **휴면** — 가시성을 잃되 존재는 유지되는 상태. 망각은 가시성의 박탈이지
   존재의 박탈이 아니다(§11).
4. **재부상(resurfacing)** — 휴면 항목이 다시 가시화되는 것.
5. **채택** — 사용자가 승격 후보를 검토 대상으로 골라 두는 표시. 워크플로우의
   편의 장치이며, 승격이나 서명이 아니다.
6. **승격 후보** — 서로 다른 맥락에서 2회 이상 검색된 Sensemaking 노드.
   브리핑 상단에 부상한다.
7. **잔류 지식** — 판별 3문(헌법 8조 3항)에 모두 해당하여 자기 Synthesis에
   잔류하는 지식. *(구 "스코프 지식")*
8. **공고화** — 노드가 기존 지식과의 관계가 배선되고, 발견된 충돌의 상태가
   명시된 상태에 도달하는 것(헌법 12조 2항).
9. **도마(에 오르다)** — 중심부 충돌이 사용자 심의에 소환된 국면(헌법 12조
   4항)을 가리키는 관용 표현.
10. **협업 기록 / 사용자 모델** — 헌법 7조 2항의 두 에이전트 기록.
    구체 파일은 §6.

## §2. Knowledge 운영

1. Domain의 신설·분화·병합은 에이전트가 제안하고 사용자가 명명·실행한다(헌법
   3조 3항). 제안은 브리핑에 실린다.
2. 노드의 Domain 배치와 임시 제목은 에이전트가 자율로 정하되, 사용자는 사후
   수정권을 가진다.

## §3. Sensemaking 운영

1. Synthesis는 작업 중 집계된 이해가 필요할 때 에이전트가 관련 Observation을
   읽고 하나의 질문이나 의미를 중심으로 응집하거나 갱신한다. 기존 Knowledge는
   필요에 따라 참조할 수 있다. 엔진은 의미 응집과 Scope의 locality 신호를 바탕으로
   후보를 제안한다. 응집된 Synthesis의 분화·병합·재배정은 헌법 4조 3항에 따라
   자동화가 기본이다.
2. 자동 재편은 브리핑에 보고된다. 사용자는 어느 재편이든 되돌리거나 Synthesis를
   **고정(pin)**할 수 있다 — 고정된 Synthesis는 자동 재편에서 제외된다.
3. Synthesis의 검색·브리핑 가시성은 마지막 관측·검색 이후 **3개월**에 걸쳐
   점진적으로 낮아진다. 3개월 동안 활동이 없으면 휴면하여 가시성이 크게
   강등된다. 새 관측·검색은 경과 시간을 초기화하며, 재부상은 §11을 따른다.

## §4. Observation 운영

1. **작성 원칙**: Observation은 에이전트가 작성하는 출처 기반의 사실
   보고다. 세션 로그, 활동 산출물, 외부 자료는 생성되었다는 이유만으로 편입하지
   않는다. 사용자는 별도의 인입 절차를 수행하지 않는다.
2. **작성 시점**: 작업 밖에서도 재사용할 사실, 감사·재현에 필요한 근거, 이후의
   판단을 바꿀 수 있는 관측을 보고한다. 보고 작성 여부의 검토는 작업 절차지만,
   노드 생성량은 목표나 할당량이 아니다.
3. **기록 형식**:
   - 반복해서 쓰는 현행 사실은 대상·속성·맥락별 정본 한 벌을 두고, 새로운
     관측·확인 또는 권위 있는 지정에 따라 갱신한다. 근거와 마지막 갱신·확인
     시점을 남기며, 충돌은 미결로 표시한다.
   - 감사·재현에 필요한 증거는 특정 시점의 발췌나 스냅샷으로 고정한다.
     고정된 기록은 수정하지 않고, 오류는 원 기록을 가리키는 정정 기록으로 밝힌다.
4. 보고는 관측이 발생한 활동·출처의 Scope에 배속되며, locality 신호(주제·활동·
   시간·출처)를 메타데이터로 보존한다.
5. 상위 층의 노드가 갱신 가능한 현행 정본의 특정 상태를 근거로 삼을 때에는
   참조 시점의 스냅샷을 고정한다. 스냅샷은 대상 노드의 식별자와 해당 상태를
   포함한 git 커밋 해시로 지정한다. 단순 열람을 위한 Link는 고정 대상이 아니다.

## §5. Workbench 운영

1. **개설**: 에이전트는 작업 단위로 Workbench를 연다. 개설 시 대응 작업과 근거
   Scope 참조(헌법 6조 2항)를 메타데이터로 선언한다.
2. **저자 표기**: Workbench는 작업 공간 전체에 적용되는 저자 표기를 둘 수
   있다(기본값 `author: agent:<하네스>`). 공간 표기가 있으면 개별 서술의 표기는
   생략할 수 있되, **사용자 저작과 외부 인용은 언제나 별도로 표시한다.** 이관 시
   저자·출처 표기를 보존한다.
3. **저자·Scope 식별 형식**: frontmatter의 `author:` 필드는 `user` 또는
   `agent:<하네스>`(예: `agent:claude`)로 적고, `scope: "[[대응 Scope]]"`를 함께
   둔다. 시스템은 에이전트의 작업 연속성을 세션이 아니라 Scope 단위로 식별한다.
   혼합 문서의 부분 표기는 인용 블록에 출처를 붙이는 방식으로 한다.
4. **조회 범위**: Workbench는 대응 작업의 맥락에서만 로드된다(헌법 6조 3항).
   교차 열람(다른 작업의 Workbench 열람)은 기본 차단이며, 사용자 지시로만
   허용된다. 열람으로 가져온 내용은 근거로 인용할 수 없고, 앵커된 관측·지식에서
   재도출한다.
5. **종료와 이관 검토**: Workbench를 종료하거나 보존 상태로 전환할 때 에이전트는
   작업 밖에서도 필요한 내용을 검토한다. 사실 보고는 Observation, 응집된 이해는
   Sensemaking, 세션과 기기를 잇는 맥락은 에이전트 기록으로 이관한다. 이 검토는
   의무 단계지만 노드 생성을 강제하지 않는다. 나머지는 Workbench 안에서
   보존하거나 위생 규칙에 따라 정리한다. 종료는 Observation 스냅샷을 만들지
   않는다.
6. **보존과 재개**: 명시적으로 종료된 Workbench는 보존 상태로 전환한다. 그 밖의
   활성 집합은 최근 1개월 안에 활동한 Workbench와 최근 활동한 Workbench
   30개(가변 기본값)의 합집합이며, 이 집합에서 벗어나면 보존 상태로 전환한다.
   보존은 Workbench 안에서 제자리로 이루어지고, 재개는 그 Workbench를 다시 여는
   방식으로 한다. 열린·보존 전환된 Workbench 현황은 브리핑에 실린다.

## §6. 에이전트 기록 운영

1. **파일 지정**: 에이전트 기록 Scope는 Observation Layer의 전용 디렉토리이며,
   다음을 담는다 —
   - **사용자 모델**: `user.md` 한 벌(정본, 헌법 7조 4항).
   - **협업 기록**: `MEMORY.md`(인덱스) + 주제 파일들.
2. **편집 이력**: 에이전트 기록의 변경 이력은 git 커밋으로 남긴다. 이 이력은
   평상시의 갱신을 막지 않으며, 3-Layer 노드가 특정 상태를 근거로 삼을 때
   6항의 고정 지점으로 사용한다.
3. **정본과 포인터**: 다른 프로젝트의 에이전트 기억은 사용자에 관한 내용을
   복제하지 않고 `user.md`를 가리키는 포인터 + 프로젝트 고유 함의만 갖는다.
4. **대조 스캔**: 주 1회(브리핑 생성 시), `user.md`의 주장을 사용자에 관한
   서명된 Knowledge와 대조한다. 충돌 발견 시 서명된 Knowledge가 우선하며(헌법
   7조 6항), 수정 제안이 브리핑에 실린다.
5. **하네스 연동**: 에이전트 하네스는 고정 경로에서 기억을 읽으므로 vault 내
   정본과의 연결이 필요하다.
   > **[미결 4]** 주 사용 하네스의 실제 제약, 하네스 독립성, drift 가능성을 함께
   > 검증한 뒤 정본 연결 방식을 정한다. 심링크와 미러링은 모두 보류한다.
6. 3-Layer 노드가 에이전트 기록을 근거로 삼을 때 가리키는 "참조 시점의
   스냅샷"(헌법 7조 7항)은 §4.5와 같이 대상 기록의 식별자와 해당 상태를 포함한
   git 커밋 해시로 지정한다.

## §7. 응집과 승격 워크플로우

1. **Synthesis의 응집**: 에이전트가 하나 이상의 Observation 보고를 발췌·재서술하고
   하나의 질문이나 의미를 중심으로 응집하여 새로운 Synthesis를 만들거나 기존
   Synthesis를 갱신한다. 기존 Knowledge는 필요에 따라 참조할 수 있다. **신규
   응집의 조성 기본값은 발췌 + 인덱스 + 배선 후보다.** 성숙 과정의 수정(헌법
   4조 4항)에서는 저자 표기 아래 종합 서술이 허용된다. 근거가 된 Observation은
   자기 층에 남고 Synthesis가 이를 Link한다(헌법 8조 2항).
2. **Workbench → 층 이관**: 헌법 6조 5항. 이관된 노드는 저자 표기를 보존하고
   각 층이 요구하는 출처를 갖춘 미서명 노드로서 편입 규칙을 따른다. 이관을 수행한
   Workbench가 이관된 노드를 Link하여 작업 맥락과 작업물의 대응을 남긴다. 이관된
   3-Layer 노드는 Workbench를 참조하지 않는다.
3. **Sensemaking → Knowledge**: 승격은 서명과 독립된 층 이동이다.
   1. 사용자가 후보를 채택한다(브리핑에서 또는 직접).
   2. 엔진이 판별 3문의 결과, 관련 노드, 목표 Domain, 배선 초안과 충돌 후보를
      제시한다.
   3. 사용자가 승격 여부와 목표 Domain, 배선 초안을 판정한다.
   4. 에이전트가 같은 노드를 사본 없이 이동하고 승인된 배선·정리를 적용한다.
   5. 승격 전의 서명 상태는 층 이동과 별도로 다룬다. 승격 과정이 봉인 경계의
      상태를 바꾸지 않으면 기존 서명이 유지되고, 바꾸면 서명이 풀린다(§8.3).
      미서명 노드는 승격 뒤에도 미서명이다.
4. **상한**: 에이전트의 Knowledge Layer 미서명 노드 생성은 세션당 **3건**.
   Synthesis 응집·Workbench·Observation 기록에는 상한이 없다.
   > **[미결 5]** 구 미결 C의 계승 — Workbench 합법화로 초안 압력이 해소됐으므로
   > 유지를 추천한다. 판례로 완화하거나 폐지하는 대안이 있다.

## §8. 서명 구현

1. **독립 절차**: 서명은 어느 3-Layer에서든 별도로 이루어질 수 있으며 승격과
   결합하지 않는다. 구현은 다음 트랜잭션을 따른다:

   (1) 사용자가 서명할 노드를 고른다.

   (2) 엔진이 현재 본문·배선과 충돌 후보를 제시한다.

   (3) 사용자가 확인하고 서명 동작을 실행한다. 이 행위는 트랜잭션을 개시하지만,
   상태 해시와 서명 기록은 아직 확정되지 않는다. 선택적 사유 한 줄은 배선 추출의
   원문이 된다.

   (4) 정합성 검사가 돈다(헌법 12조 1항). 충돌이 발견되면 사건화하고, 사용자가
   확인한 배선 초안에 따른 Predicate Edge와 사건 상태를, 헌법 10조 4항이 허용하는
   층과 상대 노드에 한해 최종 상태에 준비한다(§10).

   (5) 에이전트가 frontmatter·Predicate Edge 기입과 정리를 최종 상태에 적용한다.

   (6) 엔진이 최종 상태를 해싱하고, 사용자의 서명 행위와 그 해시를 대응시켜 서명
   기록과 파일 상태를 함께 확정한다. 사용자 확인 뒤 새로운 판단이 필요한 변경이
   생기면 확정을 중단하고 사용자 확인으로 돌아간다. 해시 확정 뒤에는 본문이나
   Predicate Edge를 추가하지 않는다.

   서명 기록은 엔진 DB에 저장한다: 노드 ID, 서명 시점, 서명 대상 상태의 해시,
   선택적 사유. 서명 기록은 검증 기록이므로 DB 소실 시 전 노드가 미서명으로
   강등될 뿐 지식은 소실되지 않는다.
2. **해시 대상** = 본문 전문 + 노드가 선언하는 frontmatter 항목(Predicate Edge,
   저자 표기 등). 엔진이 자동 기입하는 메타데이터는 제외한다.
3. **봉인 경계** *(구 미결 D의 해소 — Link/Predicate Edge 분리의 귀결)*:
   - **깨는 것**: 본문 수정(본문 Link의 추가·삭제 포함 — Link는 본문의 일부다),
     그 노드가 선언한 Predicate Edge의 추가·삭제·상태 변경.
   - **깨지 않는 것**: 다른 노드에서 들어오는 Link·Predicate Edge, 측정값
     (중심성)의 변동, 엔진의 자동 메타데이터, Domain·Synthesis의 재배치 및
     승격만으로 생기는 포함 위상의 변경.
   - 재배치나 승격 과정에서 본문·Link·그 노드가 선언한 Predicate Edge가 변경되면
     그 변경은 봉인을 깬다. 서명 노드의 재배치는 브리핑에 보고된다.
4. 서명이 풀린 노드는 diff 확인 대기로 브리핑에 오른다. 재서명 전까지 미서명
   신분이다(헌법 9조 2항).

## §9. Link와 Predicate Edge 구현

1. **선언 위치**: Predicate Edge는 관계의 **후행 노드**(나중에 서명되는 쪽)의
   frontmatter에 정확히 한 벌 선언된다. 선행(기존 서명) 노드의 봉인은 남의
   선언으로 깨지지 않는다. 역방향 시야는 엔진이 컴파일한다(backlink 방식).
2. **스키마**:
   ```yaml
   edges:
     supported-by: ["[[근거 노드]]"]        # 근거 --supports--> 이 노드
     contradicts:
       - target: "[[상대 노드]]"
         state: open                        # open | resolved | preserved
         case: 2026-07-17-01                # 사건 장부 키(감지일-일련)
     replaces: ["[[구판 노드]]"]
   ```
   > **[미결 7]** Predicate Edge의 선언 위치·방향·스키마는 추가 토론 후 확정한다.
3. **컴파일 규칙**: 본문 Link만 기본 의존(중심성의 약한 사전확률)으로 컴파일한다.
   frontmatter의 노드 지시는 Predicate Edge 선언의 주소 표기일 뿐, 기본
   의존으로 산입하지 않는다(이중 계상 방지). Workbench에서 나가는 참조는 전부
   비산입(헌법 6조).
4. **중심성 컴파일**: 인덱싱 시 계산. 입력 = 본문 Link 방향(약한 사전확률) +
   supports 하중(유효 서명 Predicate Edge만). 미서명·Workbench
   배제(헌법 11조 3항).

## §10. 정합성 검사 구현

1. 구성은 hybrid다: 임베딩 유사도 + Predicate Edge 그래프 + LLM 판정. **LLM
   판정은 recommend-only, no veto** — 검사기도 착각한다.
2. 주기 스캔은 주 1회. 스캔 대상은 유효 서명 노드 사이의 충돌이다. 미서명
   노드의 충돌은 서명 시 검사에서만 본다. 휴면 항목은 스캔 가시권에 있다.
   주기 스캔은 신규·갱신된 Observation과 서명 노드 사이의 근접·긴장 검사도
   포함한다. Observation은 Predicate Edge의 당사자가 될 수 없으므로 이 결과는
   사건화하지 않고 관측 영향 검토 후보로 브리핑에 올린다.
3. **판정 기준** — 충돌은 절차 범주(검사기가 사건화), 모순은 심의 판정이다:
   - **모순** = 사용자가 보유한 두 지식이 동시에 참일 수 없음.
     시험: "둘 다 참일 수 있는가?"
   - **supports** 시험: "근거 노드가 뒤집히면 이 노드의 근거가 흔들리는가?"
     (= 개정 비용의 국소 단위)
   - **replaces** 시험: "같은 물음에 대한 답인가, 그리고 사용자가 이미 한쪽을
     택했는가?"
   - **기각 4종**(모순 아님): **대항**(상대항이 보유 지식이 아니라 보고·인용된
     타인의 입장 — "주장 A와 달리 나는~"), **별개**(닮았으나 다른 물음),
     **중복**(같은 주장 두 벌 — 처방은 심의가 아니라 병합), **관점차**(같은
     대상, 다른 좌표 — 각자의 틀 안에서 양립).
4. **사건 생애**: 감지 → contradicts Predicate Edge를 `open`으로 등록 →
   심의 출구는 셋 — `resolved`(한쪽 개정, 전형적으로 replaces 계보를 낳는다),
   `preserved`(양립 불가를 인지한 채 보존), **기각**(모순 아님 → Predicate Edge
   소멸 + 장부 기록). 기각은 상태가 아니라 퇴장이다. 동일한 서명 상태의 쌍은
   재소송되지 않는다.
5. 라우팅 임계(중심부/주변부)는 중심성 분포에 따라 엔진이 보정하되, 보정 로직의
   변경은 브리핑에 보고한다.

## §11. 망각과 주의

1. **원칙: 전부 수집하지 않으며, 사용자의 주의를 요구하는 표면은 유한하다.**
   Observation은 재사용·감사·판단 근거의 가치가 있는 사실 보고만 담고, 이미
   3-Layer에 편입된 노드는 아래 규칙에 따라 가시성을 조절한다.
2. 미서명 Knowledge 노드는 생성 또는 마지막 검색으로부터 **한 달**간 주의
   표면(브리핑·활성 목록)에 머물고, 그 후 휴면한다. 검색 히트는 시계를 리셋한다.
3. 차등: 사용자가 직접 쓴 미서명 메모는 휴면하지 않는다 — 직접 쓴 것은 그
   자체로 주목의 산물이다. 쌓여서 어지러우면 사용자 지시로 "느린 휴면"으로
   조정할 수 있다.
4. 재부상의 세 경로: ①새 노드·활동이 휴면 항목과 의미적으로 닮으면 자동 부상
   ②정합성 검사는 휴면을 본다 ③사용자의 명시 검색.
5. 서명된 지식은 망각되지 않는다 — 개정(replaces)만 한다.
6. 시스템은 3-Layer에 편입된 노드를 스스로 영구 삭제하지 않는다. 영구 삭제는
   사용자의 직접 행위로만 가능하다. Workbench의 미이관 임시물은 §5의 위생 규칙을
   따른다.

## §12. 주간 브리핑

1. 데몬이 주 1회 생성한다. 구성: 승격 후보 / 신규 미서명 노드 / diff 확인
   대기(서명 풀림) / 열린 충돌 사건 / 관측 영향 검토 후보 / 재부상 항목 /
   Synthesis 재편 보고 / Domain 분화 제안 / 사용자 모델 대조 결과(§6.4) /
   Workbench 현황(§5.6) / 검증 실패 보고(§14) / Review Trigger 점검.
2. **읽기는 선택이다.** 처리 의무는 없다 — 죄책감 큐를 만들지 않는다. 안 읽어도
   시스템은 돌아간다.
3. Observation의 수나 작성 빈도는 성과 지표로 삼지 않는다. 다음 현상이 반복되면
   구조 재심을 알린다:
   - 필요한 사실 보고가 없어 같은 작업 맥락이나 사실을 반복해서 재구성한다.
   - 근거로 삼은 Observation 또는 Knowledge를 추적할 수 없는 Synthesis가 쌓인다.
   - 승격 후보의 장기 정체가 현재 작업을 방해한다.

## §13. 권한 차등과 판례 대장

1. 결정 층위별 권한(헌법 13조 2·3항의 시행):

   | 층위 | 예 | 권한 |
   |---|---|---|
   | 헌법적 | 층 구조, 술어, 서명·승격 규칙 | 원소별 비준 |
   | 중간 | Domain 신설·명명 | 에이전트 제안 → 사용자 명명·실행 |
   | 운영 | 노드 배치, 임시 제목, Synthesis 재편, Workbench 내부 | 에이전트 자율 + 사용자 사후 수정권 |

2. 모호하면 승인제가 기본값이다(헌법 13조 3항).
3. **판례 대장** — 자율권 확대는 여기 기록된 것만 유효하다. 회수 가능하다.
   서명은 판례의 대상이 아니다(헌법 9조 3항).

   | 날짜 | 부여된 자율권 | 근거 |
   |---|---|---|
   | 2026-07-07 | Synthesis(구 스코프)의 재배치·재배정·분화 자동화 | 헌법 4조 3항 (창립 비준) |

## §14. 엔진 상시 검증 제약

이 목록은 헌법 조문의 **인용**이며 독자적 권위가 없다. 엔진이 상시 검증하고,
위반은 브리핑에 보고된다.

1. 서명 기록은 사용자 행위로만 생성된다 — 대행 불가. (헌법 9조 3항)
2. 미서명 노드: Predicate Edge 없음, 중심성·supports 배제, 검색 후보
   표기·강등. (헌법 10조 4항, 11조 3항)
3. Workbench: 전역 질의 제외, Predicate Edge 없음, 참조 비산입,
   3-Layer 노드와 에이전트 기록의 Workbench 참조 없음. 이관 시 Workbench에서
   이관된 노드로 향하는 Link 유지. (헌법 6조 3·4항, 7조 7항, §7.2)
4. 에이전트 저작 미표시 서술의 검출. (헌법 9조 3항)
5. 같은 정보의 살아있는 사본 감지(중복 금지). (헌법 8조 2항)
6. Observation의 보존 형식 검증 — 현행 정본의 중복, 고정 기록의 제자리 수정,
   갱신 가능한 정본을 특정 상태로 고정하지 않은 근거 참조를 감지한다.
   (헌법 5조 3항, 7조 7항, §4.3·5)
7. 시스템 발의 영구 삭제 없음. (§11.6)
