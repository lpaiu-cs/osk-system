# knowledge-vault 시행령 (Bylaws) — 개정 초안

> 헌법([[Constitution]], 2026-07-17 용어 개정판) 아래의 운영 기본값이다. 헌법이
> 무엇과 왜를 정하면, 시행령은 어떻게를 정한다. 개정은 헌법보다 가볍다 —
> 사용자 지시 또는 판례 축적(§13)으로 바뀐다. 이 문서의 어떤 조항도 헌법을
> 넘어서지 못한다.
> 비준 시 구 [[Bylaws]](2026-07-06)를 supersede한다. 에이전트 저작 초안이며,
> [미결] 표기는 사용자 판정 대기 항목이다.

## §1. 어휘

1. **용어 원칙**: CS·인지과학에서 원어가 통용되는 개념은 원어로, 자연스러운 관용
   한국어가 있으면 한국어로 쓴다. 번역투 조어는 금지한다.
2. **용어 이행 표** — 2026-07-17 용어 개정 이전의 문서(구 시행령, 결정 기록,
   분류 전표)를 읽을 때 적용한다:

   | 구 문서의 용어 | 현행 용어 |
   |---|---|
   | 스코프, Scope Layer | **Synthesis**, Sensemaking Layer |
   | 관측 클러스터 | **Scope** |
   | (Knowledge의) 클러스터 | **Domain** |
   | 작업대 | Workbench |
   | 술어 엣지 | Predicate Edge |
   | 불변식 | (범주 폐지) → 조문 + §14 검증 제약 |

3. **휴면** — 가시성을 잃되 존재는 유지되는 상태. 망각은 가시성의 박탈이지
   존재의 박탈이 아니다(§11).
4. **재부상(resurfacing)** — 휴면 항목이 다시 가시화되는 것.
5. **채택** — 사용자가 승격 후보를 서명 대기로 골라 두는 표시. 워크플로우의 편의
   장치이며, 서명이 아니다.
6. **승격 후보** — 서로 다른 맥락에서 2회 이상 검색된 미서명 노드. 브리핑 상단에
   부상한다.
7. **잔류 지식** — 판별 3문(헌법 8조 4항)에 모두 해당하여 자기 Synthesis에
   잔류하는 지식. *(구 "스코프 지식")*
   > ~~**[미결 1]** 명명 판정 — 추천: 잔류 지식. 대안: Synthesis 지식.~~
   > **판정: 잔류 지식 채택.**
8. **공고화** — 노드가 기존 지식과의 관계가 배선되고, 발견된 충돌의 상태가
   명시된 상태에 도달하는 것(헌법 12조 2항).
   > ~~**[미결 2]** 용어 존치 여부 — 존치 시 위 정의로 확정. 구 후보("유효한 서명~~
   > ~~상태 도달")는 폐기됨.~~
   > **판정: 공고화 존치.**
9. **도마(에 오르다)** — 중심부 충돌이 사용자 심의에 소환된 국면(헌법 12조
   4항)을 가리키는 관용 표현.
10. **협업 기록 / 사용자 모델** — 헌법 7조 2항의 두 에이전트 기록.
    구체 파일은 §6.

## §2. Knowledge 운영

1. Domain의 신설·분화·병합은 에이전트가 제안하고 사용자가 명명·실행한다(헌법
   3조 3항). 제안은 브리핑에 실린다.
2. 노드의 Domain 배치와 임시 제목은 에이전트가 자율로 정하되, 사용자는 사후
   수정권을 가진다.

## §3. Sensemaking 운영

1. Synthesis의 생성·분화·병합·재배정은 엔진이 자동 수행한다(헌법 4조 3항).
   판단 근거: 의미 응집(임베딩)과 Scope의 locality 신호. 초점을 잃을 만큼
   넓어진 Synthesis는 분화하고, 활동이 끊긴 Synthesis는 휴면시킨다.
2. 자동 재편은 브리핑에 보고된다. 사용자는 어느 재편이든 되돌리거나 Synthesis를
   **고정(pin)**할 수 있다 — 고정된 Synthesis는 자동 재편에서 제외된다.
3. Synthesis 휴면: 마지막 관측·검색으로부터 **3개월** 활동이 없으면 검색에서
   강등된다. 재부상은 §11을 따른다.
   > **[미결 3]** 기간 기본값 3개월 — 구 미결 B의 계승 제안.

## §4. Observation 운영

1. **자동 수집이 기본이다**(헌법 5조 3항). 세션 로그, 활동 산출물, 외부 자료
   스크랩, 외부 실체의 인덱스는 데몬과 에이전트가 활동의 부산물로 남긴다.
   사용자에게 인입 절차를 요구하지 않는다.
2. 관측은 발생한 활동·출처의 Scope에 배속되며, locality 신호(주제·활동·시간·
   출처)를 메타데이터로 보존한다.
3. 외부 실체 인덱스의 형식: 정체(이름·종류) / 위치(경로·URL) / 소속(관련
   Scope·Synthesis Link) / 상태(활성·휴면). 인덱스는 내용을 포함하지 않으며,
   데몬이 주기적으로 위치의 유효성을 점검한다.
4. 원자료 보존의 이행: 에이전트는 기존 관측을 수정하지 않고 새 관측을
   추가한다(헌법 5조 1항). **예외는 에이전트 기록 Scope뿐이다**(헌법 7조 3항,
   이행은 §6). 사용자는 언제나 예외다(헌법 13조 5항).

## §5. Workbench 운영

1. **개설**: 에이전트는 작업 단위로 Workbench를 연다. 개설 시 대응 작업과 근거
   Scope 참조(헌법 6조 2항)를 메타데이터로 선언한다.
2. **저자 표기**: Workbench는 작업 공간 전체에 적용되는 저자 표기를 둘 수 있다
   (기본값 ~~`author: agent`~~ `author: agent:<하네스>`). 공간 표기가 있으면 개별 서술의 표기는 생략할 수
   있되, **사용자 저작과 외부 인용은 언제나 별도로 표시한다.** 스냅샷과 이관
   시 저자·출처 표기를 보존한다.
3. **~~저자 식별자 형식~~ 저자·Scope 식별 형식**:
   ~~frontmatter `author:` 필드 — `user` 또는 `agent:<이름>`(예: `agent:claude`).~~
   frontmatter의 `author:` 필드는 `user` 또는 `agent:<하네스>`(예:
   `agent:claude`)로 적고, `scope: "[[대응 Scope]]"`를 함께 둔다. 시스템은
   에이전트의 작업 연속성을 세션이 아니라 Scope 단위로 식별한다. 혼합 문서의
   부분 표기는 인용 블록에 출처를 붙이는 방식으로 한다.
4. **조회 범위**: Workbench는 대응 작업의 맥락에서만 로드된다(헌법 6조 3항).
   교차 열람(다른 작업의 Workbench 열람)은 기본 차단이며, 사용자 지시로만
   허용된다. 열람으로 가져온 내용은 근거로 인용할 수 없고, 앵커된 관측·지식에서
   재도출한다.
5. **보존과 재개**: ~~명시적 종료 또는 활동 중단 **1개월**(제안)에 보존 상태로
   전환한다.~~ 명시적으로 종료된 Workbench는 보존 상태로 전환한다. 그 밖의
   활성 집합은 최근 1개월 안에 활동한 Workbench와 최근 활동한 Workbench
   30개(가변 기본값)의 합집합이다. 이 합집합에서 벗어난 Workbench는 보존
   상태로 전환한다. 보존 = ~~마지막 상태의 스냅샷을 Observation의 해당 Scope에
   낙하~~ Workbench의 마지막 상태를 Observation의 해당 Scope에 스냅샷으로 보존
   + Workbench 목록에서 비활성화. 재개는 ~~보존본에서 새로 연다.~~ 보존된
   스냅샷에서 다시 연다.
6. **위생**: 방치된 Workbench는 5항의 휴면 전환이 자동 처리한다. 열린·보존
   전환된 Workbench 현황은 브리핑에 실린다.

## §6. 에이전트 기록 운영

1. **파일 지정**: 에이전트 기록 Scope는 Observation Layer의 전용 디렉토리이며,
   다음을 담는다 —
   - **사용자 모델**: `user.md` 한 벌(정본, 헌법 7조 4항).
   - **협업 기록**: `MEMORY.md`(인덱스) + 주제 파일들.
2. **이력 보존의 이행**: "변경 이력은 스냅샷으로 보존한다"(헌법 7조 3항)는 git
   커밋 이력이 이행한다. 데몬의 주기 커밋이 스냅샷 생성을 겸한다.
3. **정본과 포인터**: 다른 프로젝트의 에이전트 기억은 사용자에 관한 내용을
   복제하지 않고 `user.md`를 가리키는 포인터 + 프로젝트 고유 함의만 갖는다.
4. **대조 스캔**: 주 1회(브리핑 생성 시), `user.md`의 주장을 사용자에 관한
   서명된 Knowledge와 대조한다. 충돌 발견 시 서명된 Knowledge가 우선하며(헌법
   7조 6항), 수정 제안이 브리핑에 실린다.
5. **하네스 연동**: 에이전트 하네스는 고정 경로에서 기억을 읽으므로 vault 내
   정본과의 연결이 필요하다.
   > ~~**[미결 4]** 방식 판정 — 추천: **심링크**(살아있는 사본이 한 벌로 유지 —~~
   > ~~중복 금지 원칙의 이행). 하네스가 심링크를 따르지 못하면 차선: 단방향~~
   > ~~미러링 + vault 정본 선언. 물리 재구조화 단계에서 검증 후 확정.~~
   > **[미결 4]** 주 사용 하네스의 실제 제약, 하네스 독립성, drift 가능성을 함께
   > 검증한 뒤 정본 연결 방식을 정한다. 심링크와 미러링은 모두 보류한다.
6. 3-Layer 노드가 에이전트 기록을 근거로 삼을 때 가리키는 "참조 시점의
   스냅샷"(헌법 7조 7항)은 해당 시점의 git 커밋 해시로 지정한다.

## §7. 승격 워크플로우

1. **Observation → Sensemaking (증류)**: 에이전트가 관측을 발췌·응집·재서술하여
   미서명 노드를 만든다. **신규 증류의 조성 기본값은 발췌 + 인덱스 + 배선
   후보다.** 성숙 과정의 수정(헌법 4조 4항)에서는 저자 표기 아래 종합 서술이
   허용된다. 원자료 참조를 명시한다(헌법 8조 2·3항).
2. **Workbench → 층 이관**: 헌법 6조 5항. ~~출처(Workbench·원 관측)와 저자 표기를
   붙인 미서명 노드로 이관하며, 각 층의 편입 규칙을 따른다.~~ 이관된 노드는
   저자 표기를 보존하고 각 층이 요구하는 출처를 갖춘 미서명 노드로서 편입 규칙을

   대응을 남긴다. 이관된 3-Layer 노드는 Workbench를 참조하지 않는다.
3. **Sensemaking → Knowledge**: 후보 발굴과 배선 초안은 에이전트가, 서명은
   사용자가, 실행은 에이전트가 한다.
   1. 사용자가 후보를 채택한다(브리핑에서 또는 직접).
   2. 엔진이 관련 노드·배선 초안·충돌 후보를 제시한다.
   3. ~~사용자가 확인하고 서명한다 — 선택적 사유 한 줄은 배선 추출의 원문이 된다.~~
      사용자가 제시된 본문과 배선 초안을 확인하고 서명 절차의 실행을 승인한다.
      이 행위는 서명 트랜잭션을 개시하며, 상태 해시와 서명 기록은 아직 확정되지

   4. ~~정합성 검사가 돈다(헌법 12조 1항). 충돌이 발견되면 사건화된다(§10).~~
      정합성 검사가 돈다(헌법 12조 1항). 충돌이 발견되면 사건화하고, 사용자가
      확인한 배선 초안에 따른 Predicate Edge와 사건 상태를 최종 상태에 준비한다
      (§10).
   5. ~~에이전트가 이동·엣지 기입·정리를 실행한다.~~ 에이전트가 이동·frontmatter·
      Predicate Edge 기입·정리를 최종 상태에 적용한다.
   6. 엔진이 최종 상태를 해싱하고, 사용자의 서명 행위와 그 해시를 대응시켜 서명
      기록과 파일 상태를 함께 확정한다. 사용자 확인 뒤 새로운 판단이 필요한
      변경이 생기면 확정을 중단하고 사용자 확인으로 돌아간다. 해시 확정 뒤에는
      본문이나 Predicate Edge를 추가하지 않는다.
4. **상한**: 에이전트의 Knowledge Layer 미서명 노드 생성은 세션당 **3건**.
   증류·Workbench·Observation 기록에는 상한이 없다.

## §8. 서명 구현

1. 서명 기록은 ~~엔진 DB에 저장한다~~ §7.3의 6단계에서 최종 상태의 해시가 계산된
   뒤 엔진 DB에 저장한다: 노드 ID, 서명 시점, 서명 대상 상태의 해시, 선택적 사유.
   서명 기록은 검증 기록이므로 DB 소실 시 전 노드가 미서명으로 강등될 뿐 지식은
   소실되지 않는다.
2. **해시 대상** = 본문 전문 + 노드가 선언하는 frontmatter 항목(Predicate Edge,
   저자 표기 등). 엔진이 자동 기입하는 메타데이터는 제외한다.
3. **봉인 경계** *(구 미결 D의 해소 — Link/Predicate Edge 분리의 귀결)*:
   - **깨는 것**: 본문 수정(본문 Link의 추가·삭제 포함 — Link는 본문의 일부다),
     그 노드가 선언한 Predicate Edge의 추가·삭제·상태 변경.
   - **깨지 않는 것**: 다른 노드에서 들어오는 Link·~~Edge~~ Predicate Edge,
     측정값(중심성)의 변동, 엔진의 자동 메타데이터.
     ~~Domain·Synthesis 재배치(포함 위상은 서명 대상이 아니다 — 단, 서명 노드의
     재배치는 브리핑에 보고된다). *(재배치 비봉인은 신규 제안 — 검토 요청)*~~
   > **[미결 6]** Domain·Synthesis 재배치로 포함 위상이 바뀔 때 서명이 풀리는지
   > 판정 대기.
4. 서명이 풀린 노드는 diff 확인 대기로 브리핑에 오른다. 재서명 전까지 미서명
   신분이다(헌법 9조 2항).

## §9. Link와 Predicate Edge 구현

1. **선언 위치**: Predicate Edge는 관계의 **후행 노드**(나중에 서명되는 쪽)의
   frontmatter에 정확히 한 벌 선언된다. 선행(기존 서명) 노드의 봉인은 남의
   선언으로 깨지지 않는다. 역방향 시야는 엔진이 컴파일한다(backlink 방식).
2. **스키마**:
   ```yaml
   edges:
     supported-by: ["[[근거 노드]]"]        # 근거 --supports--> 이 노드
     contradicts:
       - target: "[[상대 노드]]"
         state: open                        # open | resolved | preserved
         case: 2026-07-17-01                # 사건 장부 키(감지일-일련)
     replaces: ["[[구판 노드]]"]
   ```
   > **[미결 7]** Predicate Edge의 선언 위치·방향·스키마는 추가 토론 후 확정한다.
3. **컴파일 규칙**: 본문 Link만 기본 의존(중심성의 약한 사전확률)으로 컴파일한다.
   frontmatter의 노드 지시는 ~~Edge~~ Predicate Edge 선언의 주소 표기일 뿐, 기본 의존으로 산입하지
   않는다(이중 계상 방지). Workbench에서 나가는 참조는 전부 비산입(헌법 6조).
4. **중심성 컴파일**: 인덱싱 시 계산. 입력 = 본문 Link 방향(약한 사전확률) +
   supports 하중(유효 서명 ~~Edge~~ Predicate Edge만). 미서명·Workbench
   배제(헌법 11조 3항).

## §10. 정합성 검사 구현

1. 구성은 hybrid다: 임베딩 유사도 + Predicate Edge 그래프 + LLM 판정. **LLM
   판정은 recommend-only, no veto** — 검사기도 착각한다.
2. 주기 스캔은 주 1회. 스캔 대상은 유효 서명 노드 사이의 충돌이다. 미서명
   노드의 충돌은 서명 시 검사에서만 본다. 휴면 항목은 스캔 가시권에 있다.
3. **판정 기준** — 충돌은 절차 범주(검사기가 사건화), 모순은 심의 판정이다:
   - **모순** = 사용자가 보유한 두 지식이 동시에 참일 수 없음.
     시험: "둘 다 참일 수 있는가?"
   - **supports** 시험: "근거 노드가 뒤집히면 이 노드의 근거가 흔들리는가?"
     (= 개정 비용의 국소 단위)
   - **replaces** 시험: "같은 물음에 대한 답인가, 그리고 사용자가 이미 한쪽을
     택했는가?"
   - **기각 4종**(모순 아님): **대항**(상대항이 보유 지식이 아니라 보고·인용된
     타인의 입장 — "주장 A와 달리 나는~"), **별개**(닮았으나 다른 물음),
     **중복**(같은 주장 두 벌 — 처방은 심의가 아니라 병합), **관점차**(같은
     대상, 다른 좌표 — 각자의 틀 안에서 양립).
4. **사건 생애**: 감지 → contradicts ~~Edge~~ Predicate Edge를 `open`으로 등록 → 심의 출구는 셋 —
   `resolved`(한쪽 개정, 전형적으로 replaces 계보를 낳는다), `preserved`(양립
   불가를 인지한 채 보존), **기각**(모순 아님 → ~~Edge~~ Predicate Edge 소멸 +
   장부 기록). 기각은 상태가 아니라 퇴장이다. ~~같은 쌍~~ 동일한 서명 상태의
   쌍은 재소송되지 않는다.
5. 라우팅 임계(중심부/주변부)는 중심성 분포에 따라 엔진이 보정하되, 보정 로직의
   변경은 브리핑에 보고한다.

## §11. 망각과 주의

1. **원칙: 저장은 무한하되, 사용자의 주의를 요구하는 표면은 유한하다.**
   *(구 불변식 3 — 헌법 13조 6항 삭제 판정에 따라 운영 기본값으로 재배치)*
2. 미서명 Knowledge 노드는 생성 또는 마지막 검색으로부터 **한 달**간 주의
   표면(브리핑·활성 목록)에 머물고, 그 후 휴면한다. 검색 히트는 시계를 리셋한다.
3. 차등: 사용자가 직접 쓴 미서명 메모는 휴면하지 않는다 — 직접 쓴 것은 그
   자체로 주목의 산물이다. 쌓여서 어지러우면 사용자 지시로 "느린 휴면"으로
   조정할 수 있다.
4. 재부상의 세 경로: ①새 노드·활동이 휴면 항목과 의미적으로 닮으면 자동 부상
   ②정합성 검사는 휴면을 본다 ③사용자의 명시 검색.
5. 서명된 지식은 망각되지 않는다 — 개정(replaces)만 한다.
6. 시스템은 스스로 영구 삭제하지 않는다. 영구 삭제는 사용자의 직접 행위로만
   가능하다.

## §12. 주간 브리핑

1. 데몬이 주 1회 생성한다. 구성: 승격 후보 / 신규 미서명 노드 / diff 확인
   대기(서명 풀림) / 열린 충돌 사건 / 재부상 항목 / Synthesis 재편 보고 /
   Domain 분화 제안 / 사용자 모델 대조 결과(§6.4) / Workbench 현황(§5.6) /
   검증 실패 보고(§14) / Review Trigger 점검.
2. **읽기는 선택이다.** 처리 의무는 없다 — 죄책감 큐를 만들지 않는다. 안 읽어도
   시스템은 돌아간다.

## §13. 권한 차등과 판례 대장

1. 결정 층위별 권한(헌법 13조 2·3항의 시행):

   | 층위 | 예 | 권한 |
   |---|---|---|
   | 헌법적 | 층 구조, 술어, 서명·승격 규칙 | 원소별 비준 |
   | 중간 | Domain 신설·명명 | 에이전트 제안 → 사용자 명명·실행 |
   | 운영 | 노드 배치, 임시 제목, Synthesis 재편, Workbench 내부 | 에이전트 자율 + 사용자 사후 수정권 |

2. 모호하면 승인제가 기본값이다(헌법 13조 3항).
3. **판례 대장** — 자율권 확대는 여기 기록된 것만 유효하다. 회수 가능하다.
   서명은 판례의 대상이 아니다(헌법 9조 3항).

   | 날짜 | 부여된 자율권 | 근거 |
   |---|---|---|
   | 2026-07-07 | Synthesis(구 스코프)의 재배치·재배정·분화 자동화 | 헌법 4조 3항 (창립 비준) |

## §14. 엔진 상시 검증 제약

이 목록은 헌법 조문의 **인용**이며 독자적 권위가 없다. 엔진이 상시 검증하고,
위반은 브리핑에 보고된다.

1. 서명 기록은 사용자 행위로만 생성된다 — 대행 불가. (헌법 9조 3항)
2. 미서명 노드: Predicate Edge 없음, 중심성·supports 배제, 검색 후보
   표기·강등. (헌법 10조 4항, 11조 3항)
3. Workbench: 전역 질의 제외, ~~Edge 없음~~ Predicate Edge 없음, 참조 비산입,
   3-Layer 노드와 에이전트 기록의 Workbench 참조 없음. 이관 시 Workbench에서
   이관된 노드로 향하는 Link 유지. (헌법 6조 3·4항, 7조 7항, §7.2)
4. 에이전트 저작 미표시 서술의 검출. (헌법 9조 3항)
5. 같은 정보의 살아있는 사본 감지(중복 금지). (헌법 8조 2항)
6. 원자료 수정 감지 — 에이전트 기록 Scope 외 Observation의 제자리 수정 금지.
   (헌법 5조 1항, 7조 3항)
7. 시스템 발의 영구 삭제 없음. (§11.6)
