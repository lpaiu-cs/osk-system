# osk-system

에이전트의 장기 기억을 위한 지식 그래프 체계와 그 **통치 문서**.

이 저장소는 osk-system의 규범 부분을 공개한 발행 미러다. 실제 인스턴스(지식
코퍼스·엔진·대장)는 사설 저장소에 있고 여기로 나오지 않는다.

## 무엇을 푸는가

에이전트가 쓰는 지식 저장소에서는 한 가지가 계속 흐려진다 — **무엇이 사용자가
확인한 것이고 무엇이 에이전트가 만든 후보인가.** 그 구별이 흔들리면 저장소는
"그럴듯한 것이 쌓인 곳"이 되고, 회상은 신뢰할 수 없게 된다.

osk-system은 그 구별을 사람의 기억이나 관행이 아니라 **기계가 틀리지 않게
판정하도록** 만든 체계다. 세 구조가 그것을 떠받친다.

**권위를 노드 밖으로 뺐다.** 서명은 노드 안의 필드가 아니라 별도 대장의
기록이다. 에이전트가 노드를 고쳐도 권위를 고칠 수 없고, 고치면 상태 해시가
달라져 **자동으로 미서명이 된다**. 서명·해제의 발의는 사용자 전속이다.

**판정을 시간이 아니라 인과로 한다.** 대장의 각 기록은 직전 head를 참조해
인과 DAG를 이루고, 판정은 시간순 마지막이 아니라 **인과 극대**다. 여러 기기의
병합으로 극대가 하나로 정해지지 않으면 보수적으로 미서명이며, 갈래 전부를 잇는
사용자의 새 서명이 이를 해소한다. 모르면 유효라고 하지 않는다.

**외부 표면이 계약 검증의 강제 지점이다.** 에이전트가 파일을 손으로 쓰면 노드
계약도 참조 위상도 거치지 않는다. 그래서 MCP 도구를 두되, 그은 선은 "읽기
전용"이 아니라 **권위 비노출**이다 — 서명과 pin은 영구히 노출하지 않고, 노드
쓰기는 검증을 통과시켜 연다.

관통하는 태도가 하나 있다. **강제할 수 없는 것을 강제한 척하지 않는다.** 권한
검사는 적용 봉투를 기계로 평가할 수 있기 전까지 언제나 보류를 낸다.

## 이 저장소에 있는 것

```
_governance/
  Constitution.md         헌법 — 공간·노드·서명·위임·검색·사건의 기본 질서
  Bylaws.md               시행령 — 헌법이 맡긴 운영 규칙
  Mechanism.md            물리 최소 사양 — 배치, id·rid 형식, 대장 규약,
                          외부 표면(MCP) 계약, 링크 문법, 비밀값 필터
  Workbench-Contract.md   Workbench scope의 특별 지위와 정돈 규율
  records/                통치 사료 — 심의 기록·처분표·재헌법화 기록
```

처음 읽는다면 **Constitution → Bylaws → Mechanism** 순서를 권한다. Mechanism의
§3(서명 기록부)과 §6-2(외부 표면)가 위에서 말한 세 구조의 물리 사양이다.

통치 문서 4종은 사용자 서명으로 비준돼 있고, 미서명 상태로는 발행되지 않는다.
사료는 서명 대상이 아니다 — 규범이 아니라 그 규범이 어떻게 정해졌는지의 기록이다.

## 여기에 없는 것

지식 코퍼스(개념·결정·프로젝트 노드), 엔진 구현, 서명 기록부를 비롯한 모든
대장, 운영 세션 기록. 전부 사설 인스턴스에만 둔다 — 공개 미러는 규범이지
누군가의 기억이 아니다.

발행 범위는 사설 저장소의 매니페스트가 정하고, 발행은 가드를 통과해야만 이뤄진다
(지식 노드 유출 금지, 비밀값 스캔, **미서명 통치 문서 발행 금지**, 검증기 통과).

## 계보

`llm-vault` → `ltm-vault` → `osk-system`. 구 이름으로 걸린 링크는 GitHub 리다이렉트로
동작한다. v1(3계층 템플릿·DuckDB 엔진) 시절의 이력은 `legacy` 브랜치에 있다.

개정 전 판본과 구체제 문서는 이 트리에 두지 않는다 — git 이력과 `legacy`
브랜치가 이미 그 역할을 하므로, 현재 트리는 **지금 유효한 규범만** 담는다.
문서가 어떻게 자랐는지는 헌법 9·10조(개정 절차와 서명의 의미)와 `records/`가
말해 준다.
